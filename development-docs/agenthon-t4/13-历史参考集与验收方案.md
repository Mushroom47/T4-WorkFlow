# 历史参考集与验收方案

更新日期：2026-10-07。用户已确认五步方案，并要求 goal 托管整个项目直至满足全部要求。

## 目标与口径

为官网当前公开的 11 个 task 建立 78 个实体的历史结果参考集，用于后续本地实验、调试和开发验证；再取得一次真实官方评测，了解官方口径与实际分数。11 是公开 unit 数量（十个练习题加一个 EXAMPLE），不是隐藏题数量，也不是保证实际 Development 每次评测题目集合固定。

匹配键使用 `task_id` 和完整 `task.json` 的规范化 JSON SHA-256；实体集合也必须完全匹配。同一 task_id 内容变化时拒绝回放，不能通过关键词相近匹配。这里的 canonical hash 是项目内部输入指纹，不是 descriptor 的 RFC 8785/JCS digest。

参考记录包含历史实际 label/value、单位、计算输入、公式、来源 URL、发布日期/定位、状态和备注。历史实际值没有唯一的预测区间或预测推理；本地 fixture 的测试区间及引用不称为“标准预测”。官方私有 outcome、naive anchor 和部署评分细节仍未知。

## 数据质量状态

`verified` 表示公开资料和口径核对完成；不是官方真值认证，也不自动代表所有序列已证明首次发布版本。`provisional` 表示有支持性结果但证据或口径仍有明确限制；默认不纳入比较。`unresolved` 不填猜测值，不能生成固定答案。

宏观系列必须保存准确 vintage，不能用今日修订值。EPS 必须区别 GAAP/adjusted、持续经营/总 diluted EPS、实际季度日期和首次申报。信用事件的 `no_event` 需要完整窗口证据；没有搜索结果不足以证明未发生。股票反应需一致的总回报窗口、benchmark、split/dividend 核对。拍卖官方 Subtotal 不等于 API total 字段直接相除。

默认参考数值不作Final拟合或校准产物；若将来这样使用，需按[05 数据政策](05-数据模型许可与训练政策.md)与官方#24澄清另外核实首次发布值并记录provenance。0.1.1已补明确ALFRED收益率历史vintage，但原始源全球首发时点、COT首发链和历史行情完整公司行动链仍未证明，详见[版本核查](16-证据补强与版本核查.md)。

## 可复现工具与验收

`tools/build_reference_data.py` 从固定 Git blob 冻结输入、重算 COT 并合并四组研究记录。`tools/reference_suite.py` 提供 audit、fixture、validate、compare；测试区间、claims/reasons 和历史目标值分别记录。未知、被修改、缺重复实体或非法有限值必须明确失败。

质量验收包括全部 78 键登记、来源与本地证据 hash、单位/期间一致、可计算公式独立复算、受控错误测试和覆盖报告。完整运行命令、环境与结果写入 [09 进度](09-开发进度记录.md)。没有 NLI、tokenizer、私有 naive/outcome 的检查明确未执行。

官网评测许可、入口及真实返回成绩见 [14 官方评测沟通](14-官方诊断评测沟通.md)。即使固定回放本地数值误差为 0，也只证明参考集和工具管线一致。只有平台有效返回的分数是官方成绩；整体 goal 在该要求和最终交付完成前保持未完成。
