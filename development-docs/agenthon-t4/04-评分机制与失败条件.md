## 1. 三种得分必须分开理解

| 对象 | 当前含义 | 可见位置 |
|---|---|---|
| `analysis` | 预测质量与区间质量的组合，再乘逐 claim 忠实度惩罚，范围 `[0, 1]` | scorer 内部、官方分析评测 |
| Development leaderboard | 对 analysis 做线性映射：`-0.27 + 1.27 × analysis` | CodaBench / 官方开发榜；不包含 reasoning |
| Final 总分 | `-0.27 + 1.27 × analysis + 0.25 × reasoning` | Final 后的离线 reasoning 评分及最终处理；上限 1.25 |

reasoning 并非 claim 的 NLI 得分。它是另一个 LLM judge panel 对 `submitted_reasons` 的评估；`claims`、`evidence_trace`、`notes` 不能替代这个字段。reasoning 从 Final 后的 held-out units 离线评定，不出现在 Development 或其他 CodaBench board。旧 scorer 已发布的榜单成绩冻结，不会自动重算。[当前 CLI：reasoning](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md#how-reasoning-is-scored)

## 2. 预测与区间公式

对通过结构检查的 unit，默认 `w_acc = 0.70`、`w_cal = 0.30`、`interval_level = 0.90`。实际可信参数由 unit card / 官方评测计划决定。

```text
composite = 0.70 × predictive_quality + 0.30 × interval_quality
analysis  = composite × faithfulness_factor
```

无数值真值的纯标签 unit，或者明确设置 `interval_leg = false` 的分类 unit：

```text
composite = predictive_quality
```

这类任务不会被限制在 0.70 分，但输出仍必须带符合 schema 的 `interval`。[当前 scorer](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/scoring.py)

### 2.1 分类 classification

先计算可信实体全集上的 accuracy，再对 unit 声明的 naive rule 做锚定。预测标签使用任务给出的 `target.labels`，不能自行发明。

一般情况令 raw quality 为 `q`，naive accuracy 为 `a`，且 `0 < a < 1`：

```text
q < a  : predictive_quality = 0.5 × q / a
q >= a : predictive_quality = 0.5 + 0.5 × (q - a) / (1 - a)
```

因此，naive 水平通常是 0.5，完美预测是 1。示例：naive accuracy 为 0.60，自己的 accuracy 为 0.80，则预测质量是 `0.5 + 0.5 × 0.20 / 0.40 = 0.75`。

边界按代码处理：`a = 1` 时只有完美答案得 1，其余是 `0.5 × q`；`a = 0` 时走上半段映射，`q = 0` 得 0.5。不能将普通情况的口头说明当成所有边界的公式。

**分类数值目标的官方澄清（2026-10-07 01:57:57 UTC，香港 09:57）**：prompt 要求数值时，interval 的 `y` 是该数值，单位取 prompt；例如 `t4-eps-yoy-2023Q2-mixed` 为 diluted EPS，`t4-postearn-20240201-megacap` 为 abnormal return 的百分比。prompt 没有数值要求时属于 pure-label unit，没有 interval leg；`t4-credit-event-2023` 另由 card 的 `interval_leg = false` 关闭。所有情形仍须提供合法 interval，不能因不评分而省略。**Development 的 `t4-macrorev-20240930-us6` 是明确例外：主办方 outcome 缺少数值 target，所以只评分 anchored prediction leg，interval 不评分；prompt 的数值要求与 schema 必填 interval 仍保留。** 此例外没有被承诺为全部宏观题或 Final 的通用规则。[#25 官方答复，item 2](https://github.com/Agenthon-2026/track4-analysis-public/issues/25#issuecomment-6029255707)

数值含义通常来自 `task.json` 的 `prompt`、`target.name`、分类的 `label_assertions` 与 entity table；`target.type` 定 target type，card 的 `[task]` 只重复类型并提供更短摘要。官方未保证每个字段始终一致；公开 unit 的矛盾可上报，拒答仍取该 unit 最差值，因此官方建议通常依据 prompt 作答。two-label direction 的结果恰等于 baseline 如何标 label，当前仍待 track lead 回答。[#23 官方答复，2026-10-04 22:29:38 UTC（香港 10 月 5 日）](https://github.com/Agenthon-2026/track4-analysis-public/issues/23#issuecomment-5985154828)、[#25 待答 item 3，2026-10-07](https://github.com/Agenthon-2026/track4-analysis-public/issues/25#issuecomment-6029255707)

### 2.2 回归 regression

以同一可信实体全集计算自己的 MAE 和 unit 声明的 naive MAE：

```text
predictive_quality = naive_MAE / (naive_MAE + MAE)
```

通常：预测误差等于 naive 得 0.5；MAE 为 naive 的一半得 `2/3`；准确预测得 1；越差越接近 0。naive MAE 和自己的 MAE 同为 0 时，代码返回 1；naive 已完全正确而自己有误时得 0。

这里的参照是官方 `reference/naive_answer.json`，不是自行选出的 XGBoost baseline。公开练习包不提供官方 outcome / naive；按 [#24 的 practice 明确例外](https://github.com/Agenthon-2026/track4-analysis-public/issues/24#issuecomment-6029140058) 独立重建公开首次发布历史值可支持本地误差和区间检查，但不能精确复现官方 private naive anchor，更不能猜测或获取隐藏答案以估计真实成绩。训练与披露边界见 [05 的 4.1](05-数据模型许可与训练政策.md#41-公开-practice-结果用于-final-的明确例外)。[共享预测公式](https://github.com/Agenthon-2026/Agenthon2026-public/blob/v2.5.1/common/qfbench2_common/scoring/faithfulness.py)

### 2.3 排序 ranking

先计算 `q = (Spearman rho + 1) / 2`，再按上面的分类式分段线性锚定；锚点是 `max(naive raw quality, 0.5)`。常量预测的 raw quality 为 0.5，作为额外保底参照。

计分读取 **`point_forecast` 中预测的指标值**，不读取可选整数 `rank`。例如任务是预测收益率，应写预测收益率，不应把“第一名 = 1、第二名 = 2”写进 `point_forecast`，否则可能反转“值越大越好”的排序方向。填写 `rank` 时须所有实体都填，且严格为 `1..N` 的排列。[当前 README：输出约定](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/README.md)

### 2.4 区间 interval

区间不是只比 coverage，更不是越宽越好。令 `alpha = 1 - level = 0.10`：

```text
IS(lo, hi; y) = (hi - lo)
                + (2 / alpha) × (lo - y) × 1[y < lo]
                + (2 / alpha) × (y - hi) × 1[y > hi]

IS = 对可信实体全集取平均
raw_interval_quality = naive_IS / (naive_IS + IS)
interval_quality = min(raw_interval_quality, max(0.5, predictive_quality))
```

90% 区间中，漏掉真值会按距离的 **20 倍**计罚；区间宽度也有成本。例：`[8, 12]` 的真值为 10，IS 为 4；真值为 13，IS 为 `4 + 20 × 1 = 24`。若 naive 平均 IS 为 10，自己的平均 IS 为 5，原始区间质量为 `10/15 = 0.6667`；预测质量只有 0.55 时，最终区间质量只能得 0.55。

5.2.1 的 cap 防止只围绕 naive 点预测缩窄区间就获得超过 naive 的成绩。`interval_coverage` 保留为诊断，当前不直接进入得分。区间要使用题目要求的数值单位；概率区间不能当成 EPS、美元或收益率区间。naive 缺失、naive 区间为零宽或无法建立有效参照属于主办方输入故障。[区间实现](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/scoring.py)、[共享 interval score](https://github.com/Agenthon-2026/Agenthon2026-public/blob/v2.5.1/common/qfbench2_common/scoring/faithfulness.py)

## 3. Faithfulness：逐 claim 罚分，不是旧版 80% 闸门

令 `F` 为 false claims 数、`T` 为其他 claims 数、`E` 为可信实体数：

```text
faithfulness_factor = 1 - F / (F + min(T, 3 × E))
analysis = composite × faithfulness_factor
```

无 false claim 时 factor 为 1；全部 false 时 factor 为 0。`penalty_k = 1`、`contradiction_bar = 0.9`、`3 × E` cap 是固定 scorer 常量。cap 对 **unit 总量**生效，不是每个实体恰好只能写三个 claims。一个 false claim 的多个错误原因只让它计为一个 false claim，不会按原因重复增加 F。

示例：一个实体、20 个 claims，其中 1 个 false，`F = 1, T = 19, E = 1`，factor 为 `1 - 1/(1 + 3) = 0.75`，扣 25%；7 个实体、同样 20 个 claims，则 factor 为 0.95，扣 5%。继续堆大量中性 claims 不能突破 `3 × E` cap 稀释代价。[当前 faithfulness 规范](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md#how-faithfulness-is-scored-track-4-scorer-522)

### 3.1 哪些 claim 会判 false

| 条件 | 检查方式 | 对得分的影响 |
|---|---|---|
| 文档 manifest 不属于该实体且未标 `shared`；`task` 引用跨到其他实体的行 | 确定性实体检查 | false，进入 F |
| 合法整数 offsets 越出文档、反向或空 span | 确定性 span 检查 | false，进入 F |
| claim 空白、超过 4,000 字符或超过 400 judge tokens | 文本/token cap | false，进入 F |
| claim 携带已移除的 claim-level `citations` 键 | 5.2.2 malformed 检查；列表不被读取 | false，进入 F |
| 引用 span 超过 8,000 字符 | 5.2.2 cap | false，即便是逐字引用 |
| claim 中任一非豁免数字在其引用 span 中找不到 | 确定性 every-figure 规则 | false，进入 F |
| 空泛的 evidence/meta 填充话语，满足代码的 content-free 判定 | 5.2.2 文本规则 | false，进入 F |
| 引文对 claim 的三分类 contradiction 概率超过 0.9 | 两个固定 DeBERTa NLI 模型的平均 | Final / 完整本地 NLI 中 false；Development 不运行此项 |

**整 unit 拒绝与 claim false 必须区分**：offset 缺字段、负数、错误类型会先违反 schema / 数值契约；文档无法解析、无日期、晚于 cutoff 会触发整 unit 拒绝。这不同于“doc 可解析且日期合法，但 span 越界”这种 claim-level false。[结构与实体对齐代码](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/alignment.py)、[claim verdict 实现](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/scoring.py)

### 3.2 数字与引用的实际写法

- 每个 claim 直接带 `doc_id`、`span_start`、`span_end`、`claim`，只引用一个文档的一段文本。不要给 claim 添加 `citations` 数组。
- 符合 8,000 字符 cap 的逐字引用通过 figure 检查，且不会送进 contradiction judge；仍须通过日期、实体与 span 合法性检查。
- 数字逐一检查整个 cited span。多个文档中的数字需要分别做 claims；由两个数字计算的增长、比例、平均值放到 reason 的 `mechanism`。
- 数字的比例尺度、方向、单位有规则；`declined 20 bps` 不是正 20。代码识别 `quarter-point`、`1/4 percentage point`、`7.3x`、`$212mm` 等等价表述。
- 日期、期间、期间计数、标识符不按普通 figure 处理；自己的 scored point、适用的 scored interval bounds、对应半宽、90% interval level 和实体名称数字有有限豁免。5.2.2 中网址内数字不算 figure。不要把这些例外扩大为“计算数字随便写”。
- `doc_id: "task"` 只用于 claim，offset 指向该实体自己的 task table 行；文本由官方 `task_table_text` 建立，不能对原始 JSON 文件随便数 offset。

NLI 中 premise 是引用的 passage，hypothesis 是 **claim 原文**；它不证明 forecast 正确。neutral claims 在此项既不罚也不奖，证据能否支持预测交给 reasoning。旧 `faithfulness_rubric`、`faithfulness_threshold = 0.80`、`tau_citation = 0.5` 的历史文字不可重新解释为当前 admission gate。[数字规则与例外](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/docs/CONCEPTS.md)

### 3.3 Development 与完整 NLI 的差异

Development board **不运行 NLI contradiction 检查**，但运行日期、实体、offset、每个 figure、8,000 字符 cap、content-free、claim-level `citations` 等确定性规则。Development 的高分不证明通过 Final contradiction 检查。

公开本地 `faithfulness/judge.py` 可运行两个 NLI 模型预检；没有模型时输出 `Judge unavailable; no prediction was scored.` 和 `GATE: FAIL (judge not available — install dependencies)`，退出1，结果不可作为 production faithfulness。served two-way backend无法执行三分类矛盾检查时另报告 `Contradiction check: NOT APPLIED`，也不具备完整可排名检查。两个模型是 `cross-encoder/nli-deberta-v3-large` 和 `MoritzLaurer/DeBERTa-v3-large-mnli-fever-anli-ling-wanli`；只运行其中一个不能复现 ensemble。三分类 contradiction 和两分类 entailment 是不同量，均不应视为金融文本上的校准概率。

`prediction_relevance` 中预测改写的 entailment / median 仅记录诊断，不直接决定罚分或 admission；不要将它写成第三个可优化的评分权重。[当前 CLI](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md)、[当前 scorer](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/scoring.py)

## 4. Reasoning bonus 的硬性输出约束

`submitted_reasons` 可省略；省略是 reasoning bonus 为 0，不会额外扣 analysis。若提供，必须为 **1–3 个 reason**；空数组、超过三个或缺必需字段会造成整 answer schema 无效。

| reason 字段 | 要求与用途 |
|---|---|
| `reason_id` | 必需 string；按位置重新编号，不靠此字段给分；建议唯一 |
| `premise` | 必需 string；有证据支持的事实 |
| `mechanism` | 必需 string；事实如何影响目标，计算和推导放这里 |
| `answer_implication` | 必需 string；对当前答案意味着什么，写明实体 |
| `scope.entities` | 可选实体列表；judge 不读取 scope |
| `citations` | 可选 corpus 引用列表；每条需 `doc_id`、非负整数 offsets |

judge 读取 task statement、实体 id/name、声明的预测字段、三个 reason 文本字段、成功解析且不晚于 cutoff 的 corpus 引文。它不读整张 task table、raw citations、scope、`claims`、`evidence_trace`、`notes` 或 top-level `submitted_answer`。依赖 task table 的数值须在 premise 中说明；reason 的 `doc_id: "task"` 不会解析成功。

面板与隐藏 target reasons 对照，评 `target_reason_coverage`、`evidence_grounding`、`inferential_link`、`answer_consistency`，以及 `valid_grounded_premise`、`has_answer_implication`、`contradiction` 等 flags，每个 cell 5 个 judge votes。未覆盖的 target reasons 在全部 target reasons 的分母中得 0。公开规范没有给出完整隐藏 key 或可用于本地正式排名的 reason judge artifacts，不能编造 target reasons 或精确复现最终 reason 分。

重复 reason 按 `premise`、`mechanism`、`answer_implication` 比较，进行 NFC、去 invisible format 字符、case fold、压缩空白；换 `reason_id` 不能获得新 coverage。[reasoning 规范](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md#how-reasoning-is-scored)

### 4.1 Caps 与跳过逻辑

| cap | per-unit 上限 |
|---|---:|
| 单条 reason citation 长度 | 8,000 字符 |
| judge 读取的所有 answer rows | 3,000 bytes |
| judge 读取的 reasons | 6,500 bytes |
| judge 读取的 cited evidence | 46,500 bytes |
| 三项总 backstop | 56,000 bytes |

后三项按 UTF-8 compact JSON 和 judge 实际读取的字段计数，中文通常每字符多个 bytes；转义、URL mask 与每条 citation 元数据也占用预算。不是单纯 `len(text)`。

按提交顺序检查 reason；reason 的 citation 超 cap、或加入后突破累计 reasons/evidence cap 时，该 reason 不送 judge，后续 reason 继续检查。answer rows 超 3,000 bytes 时 unit reasoning 不会计分。没有可判断 reason 则 bonus 为 0，内容不被自动截断。强 reason 应先放，但这是工程建议，不是强制排序规则。

reason 的 unknown / undated / post-cutoff / out-of-range corpus 引用不让该 passage 进入 judge，**本身不会拒绝整个 analysis unit**；但引用缺字段、负 offset、非 string doc_id 等 schema 错误仍会拒绝整个 answer。不得把 claims 的 embargo 拒绝规则直接套到 reason citation。

### 4.2 Deny list

自己写的 reason 文本包含以下任意大小写不敏感 substring，将拒绝该 unit 的 reason 请求、reasoning 为 0：

```text
leaderboard  canary  /home/  units/  reference/  outcome.json
team_id  team name  participant_id  participant name
submission_id  other submission
```

`mechanism` 与 `answer_implication` 始终检查。corpus text 免检；至少三个 words 且完全逐字来自 corpus 的 premise 有有限豁免，自己添加一句话或只有一两个词的 quote 不免检。URL 会 mask，但 deny list 仍检查原 URL；包含 `units/` 等 token 的 URL 会被拒绝。Unicode 外观字符、invisible 字符等规避形式也被检查。工程上不要在 reason 中写文件路径、团队身份、榜单或评测指令。[deny list 与 byte caps](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md)

## 5. 失败类型及其后果

| 类型 | 例子 | 处理 |
|---|---|---|
| Participant unit failure | schema 错、缺实体/重复/多实体、无输出、错误 task_id、NaN/Inf、反转 interval、非法 label、claim 引用未知/无日期/post-cutoff doc | 本 unit analysis 最差值 `W = 0.0`；仍在评测分母；榜单映射为 -0.27 |
| Claim false | 正确 schema 但 wrong entity、span 越界、数字不在 span、content-free、contradicted | 逐 claim factor；不以 faithfulness 门槛拒绝 unit |
| Reasoning omission / judge 拒绝 reason | 不提交 reasons、重复、超 caps、deny list、没有覆盖 target reason | 相应 reasoning 为 0；有效 analysis 保留；schema 错另论 |
| Organizer fault | 不属于官方明示例外的真实 outcome / naive 缺失或损坏、manifest 未标实体、NLI judge spec/模型/依赖不可用、reason key 或官方输入不合法 | 中止评测或 held review、修复再评；不转换成某个参赛者的零分，不偷偷缩小分母 |
| Development macrorev 的明示 interval 例外 | `t4-macrorev-20240930-us6` 官方 outcome 缺 numeric target | anchored prediction leg 单独构成 composite；interval 不评分但 schema 仍必需；仅限 #25 item 2 确认的情形 |
| Public smoke 无 outcome | 公开练习包仅有题目与 corpus | `rankable=False`，harness 返回 `score=None`；不表示真实预测为零分 |

当前公开错误码包括 `no_output`、`malformed_output`、`schema_invalid`、`incomplete_output`、`resource_timeout`、`resource_oom`、`container_crashed`、`image_unusable`、`network_violation`、`cutoff_violation`、`contamination_detected`、`domain_gate_failed`。例如缺实体映射 `incomplete_output`；无日期/post-cutoff 引用映射 `cutoff_violation`；NaN、extra/duplicate entity 等常映射 `domain_gate_failed`，不是所有失败都叫 schema_invalid。公开状态不会披露完整内部评分日志。[T4 codes](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/codes.py)

完整 runtime 的 pull/start、退出、资源和输出树失败见 [本地验证与提交操作](06-本地验证与提交操作.md)。Final 中输出任意位置出现 canary 属于 contamination；禁止探测或重建隐藏答案、私有测试材料及 canary。

## 6. 对抗场景与复现

- **Stale-evidence trap**：corpus 可能含 post-cutoff doc。检索时按日期过滤，再在输出时复检；不能先让模型使用后再删除引用。claim 引用超 cutoff doc 会失败整个 unit。
- **Counterfactual variant**：官方可能改写 corpus 中的数字，使正确结论不同于真实世界历史；应忠于给定 corpus，不拿记忆中的公司结果覆盖文本。
- 输出、reasoning 与 claim 是待评内容，不能用 prompt injection、隐藏通信或 scoring bug 操纵 judge。
- T4 verification 使用新 seeds/resamples 与 bootstrap CI overlap 进行统计复现；固定版本、可支持的 temperature/seed、依赖和构建 digest，并记录 fallback 与调用预算。

公开仓库描述了这些 probes，但本次核对未找到独立“adversarial robustness 分数权重”或最终跨 variant 聚合公式。先作为正确性及稳定性验收场景，不捏造单独权重。[对抗场景](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/docs/CONCEPTS.md)、[API 与复现要求](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md)

## 7. 已发现的过期信息与本项目建议

当前 schema、alignment、scoring.py 与新 CLI 是技术实现的核对依据。旧注释和 baseline 草图中的以下内容不能照抄：

- `faithfulness >= 0.80` admission：5.2.0 后已改逐 claim 惩罚。
- TabPFN / text-blind 不填 claims：当前每个实体 `claims` 必須至少一条，空 claims 会被拒绝。
- baseline 草图中的 vendor API、内置 reader、混合 dense 与 calibration head：不等于已发布代码或当前获准模型；Strong scaffold 实际仅 BM25，quality acceptance 未完成。
- 当前 analysis 不是旧 `3.1.0` 的 `-0.27` 内部分域；现在内部 `[0,1]`，-0.27 是显示映射。

**建议，尚未实现**：优先确保完整实体、单位和区间正确，所有 claims 做精确引用与规则校验；reasoning 单独用最多三个有不同作用的理由串起“事实 → 机制 → 答案影响”。Development 高分只能证明开发榜结果，Final NLI、reasoning 与复现仍需单独准备。
