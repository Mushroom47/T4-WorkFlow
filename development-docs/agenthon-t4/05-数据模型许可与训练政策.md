# T4 数据、模型许可与训练政策

T4 允许符合历史 cutoff 和数据许可的离线训练，也允许有限的本地非神经数值模型与校准参数。评测时的输入与引用仍只限当前任务和官方冻结语料；语言模型服务只限批准的 House 模型。本文件于2026-10-08复核规则：T4当前规则commit `458bc07efc05983de342ccb371e2b3cd793d621f`，训练政策revision `2026-10-07.1`；输入/scorer5.2.2和工具验证仍固定旧基线，toolkit `v2.5.1` / commit `50fb2dc2b39c70f4cf81fcd269943782eddfaed0`仍可使用。本文是参赛约束记录，不扩展主办方授权范围。

2026-10-07 补充核对：主办方在 [#24 的最终澄清](https://github.com/Agenthon-2026/track4-analysis-public/issues/24#issuecomment-6029140058) 明示公开 practice 首次发布结果用于常数和设计选择的独立例外，适用于每个 Final task；完整条件见 4.1。该澄清补充上述固定版本基线，不替换其他数据、模型、推理和披露约束。

## 1. 先把三种权限分清

| 问题 | 现行约束 |
|---|---|
| 可以用什么数据在离线阶段拟合、选择和校准？ | 通常须公开、合法取得、许可允许，而且相关任务的特征/标签在 cutoff 前已可获得；公开 practice 结果的明确例外见 4.1；非公开或 embargoed 数据另需明确书面授权 |
| 可以把什么模型/资产放进镜像？ | 下表允许的非神经资产及唯一例外NeMo Retriever embedding models；其他额外神经checkpoint与语言模型均不允许且没有批准通道 |
| 正式推理时可以读什么、引用什么？ | 提供的任务输入和官方冻结 corpus；不抓取外部数据、不导入外部证据文档、不引用外部 inference corpus |

离线训练资格不能推出「允许本地第二个 LLM」；包能安装也不能推出包里的任何模型都可用；模型或数据许可证允许使用，也不能推出比赛规则允许该使用。[来源：训练政策](https://github.com/Agenthon-2026/track4-analysis-public/blob/458bc07efc05983de342ccb371e2b3cd793d621f/docs/TRAINING-POLICY.md)、[本地资产政策](https://github.com/Agenthon-2026/track4-analysis-public/blob/458bc07efc05983de342ccb371e2b3cd793d621f/docs/ARTIFACT-POLICY.md)

## 2. 模型与本地资产允许矩阵

| 模型 / 资产 | 默认资格 | 必须遵守的条件 |
|---|---|---|
| 统计代码、确定性预处理和数值变换 | 允许 | 固定包/源码版本，遵守实际资源限额 |
| 已拟合 linear model、decision tree、XGBoost / LightGBM / CatBoost 等非神经预测器 | 允许 | 披露实际学得模型、拟合与选择数据；一般 cutoff 规则与 4.1 的明确 practice 例外分别记录；不得存储题目答案 lookup |
| calibration parameters、threshold、covariance estimate、prediction interval calibration | 允许 | 通常拟合、选择、校准各阶段分别满足 cutoff；若以公开 practice 首次发布值调整常数或选择设计，须满足 4.1 的条件并披露 |
| tokenizer-only vocab/config、静态字典、数值 lookup table | 有条件允许 | 数据来源合规；不携带额外神经权重或任务答案表 |
| BM25 / 非神经证据索引 | 允许 | 索引当前任务提供的官方冻结 corpus；不因此获得导入外部 inference 文档资格 |
| 额外 neural forecasting/classification model | 不允许 | 非LLM或辅助用途不豁免，没有批准通道 |
| NeMo Retriever embedding models | 唯一额外神经checkpoint例外 | starter pack推荐类别，构建时烘焙并记录准确revision/checksum；不在运行期下载，不覆盖reranker或其他NeMo模型 |
| 其他 neural embedding / neural reranker | 不允许 | 没有批准通道；retrieval用途不豁免 |
| 额外语言模型、完整 LLM 权重、participant-run LLM server | 不在比赛允许范围 | 没有第二个语言模型批准通道 |
| LoRA / adapter / `byo-small` / `byo-large` | 已撤销 | 自 2026-09-18 起没有 adapter/BYO 路径；toolkit 自 2.4.3 不再接受 `byo-*` |

所有 T4 提交的 category 为 `api`。模型自由代码 baseline 也使用此 category；它不要求虚构一个模型条目。card 授予 GPU 不等于批准额外神经模型，也不等于批准本地模型服务器。批准本地非神经资产不会增加 CPU、GPU、磁盘、内存或网络额度。[来源：本地资产政策](https://github.com/Agenthon-2026/track4-analysis-public/blob/458bc07efc05983de342ccb371e2b3cd793d621f/docs/ARTIFACT-POLICY.md)、[提交 category 与 GPU 解释](https://github.com/Agenthon-2026/track4-analysis-public/blob/458bc07efc05983de342ccb371e2b3cd793d621f/SUBMISSION_CLI.md)

工程建议：当前候选使用纯词法retrieval及普通统计量。若采用NeMo Retriever embeddings，按唯一例外构建时烘焙、记录revision/checksum并复核资源；不能把reranker、TabPFN或其他神经checkpoint列为可申请批准的能力。官方概念页或历史 baseline 提到某个模型，不等于比赛对参赛镜像该模型的批准。[来源：模型资格的明确限制](https://github.com/Agenthon-2026/track4-analysis-public/blob/458bc07efc05983de342ccb371e2b3cd793d621f/docs/ARTIFACT-POLICY.md)

## 3. House 模型与狭窄 pretraining 例外

当前 toolkit 的 House release 披露：

```json
{
  "name": "nvidia/nemotron-3-super-120b-a12b",
  "version": "rl-030326-fp8",
  "revision": "rl-030326-fp8",
  "training_cutoff": "unpublished",
  "access": "api"
}
```

这是 descriptor `models[]` 的五字段条目。`unpublished` 表示主办方没有公布训练 cutoff，不能改成推测日期。运行请求的 `model` 使用 harness 注入的 `MODEL_NAME`，不使用自己猜测的 route alias；release 中 `house` 是 route alias，与 descriptor 中模型身份不同。[来源：House 身份与披露](https://github.com/Agenthon-2026/Agenthon2026-public/blob/50fb2dc2b39c70f4cf81fcd269943782eddfaed0/docs/HOUSE-MODEL.md)

对于历史任务，general-purpose base pretraining 的特殊许可覆盖**确切批准的House base revision及上述NeMo Retriever embedding models**。这一 pretraining 许可本身不覆盖参与者的 post-cutoff adaptation、fitting、model selection、interval calibration、附加数据或其他模型；4.1 的 practice 例外来自另一条明确官方澄清。单纯填写另一个模型的 `training_cutoff` 不能得到该 pretraining 例外。[来源：训练政策例外](https://github.com/Agenthon-2026/track4-analysis-public/blob/458bc07efc05983de342ccb371e2b3cd793d621f/docs/TRAINING-POLICY.md)、[现行批准 revision](https://github.com/Agenthon-2026/Agenthon2026-public/blob/50fb2dc2b39c70f4cf81fcd269943782eddfaed0/docs/HOUSE-MODEL.md)

House 使用约束包括关闭 vendor-side web search、code execution、retrieval 和其他 vendor tools，保留固定模型身份，在支持时固定 temperature / seed，遵守代理审计和每 unit 请求预算。没有 participant vendor API key 路径，没有开放互联网，model access 不授权 fetch data。具体接口、请求上限和当前部署状态见运行与提交文档。[来源：网络与模型调用合同](https://github.com/Agenthon-2026/track4-analysis-public/blob/458bc07efc05983de342ccb371e2b3cd793d621f/SUBMISSION_CLI.md)

## 4. 离线外部训练：真正判断的是「首次可获得时间」

- 允许在 otherwise permitted 的 category / artifact 内使用外部数据离线训练。
- 数据必须公开、依法取得、许可适合该用途。雇主/赞助商非公开数据和 embargoed 数据需要明确书面授权。
- 通常，任务专用 features、labels，以及 adaptation、模型选择和区间校准所用资料，必须在每个会使用该 artifact 的任务 cutoff 之前已可获得；4.1 单列官方明示的公开 practice 例外。
- 历史 observation date 不能代替公开时间。某月指标在后月发布，或后年修订，不能按原观察月份当作当时已知值。
- 在没有适用的明确例外时，训练集满足 cutoff，不代表用未来标签做 hyperparameter selection、阈值选择或 residual calibration 合规。
- 使用同一模型覆盖多个任务时，应证明它对每个相关 cutoff 均合规，或建立 cutoff 合规的 artifact routing 与来源记录。
- 禁止把 resolved task answers 存成 lookup 表；不能因「训练资产」名义绕过 inference 数据边界。

[来源：外部训练与 historical cutoff 政策](https://github.com/Agenthon-2026/track4-analysis-public/blob/458bc07efc05983de342ccb371e2b3cd793d621f/docs/TRAINING-POLICY.md)

例如某题 `cutoff_date = 2024-09-30`：2024-09-29 已发布且许可允许的 observation 可进入合规拟合；2024-10-03 才发布的 9 月 observation 不可因归属 9 月而提前使用；未适用 4.1 例外的、2024-11 才得到的 true outcome 不可用于 9 月题的 model selection 或 interval calibration。此例说明一般政策逻辑，不涉及任何实际题目真值。

### 4.1 公开 practice 结果用于 Final 的明确例外

主办方 `PawPol` 在 **2026-10-05 19:06:03 UTC（香港 10 月 6 日 03:06）**答复：公开 practice 的历史结果可用于 Final 提交的常数设置与设计选择，包括问题中所列区间宽度 multiplier、关键词、threshold、保留哪些读取和 fallback 规则；必须取**首次发布值**，不能用后来修订值，并在 `ARTIFACT_PROVENANCE.md` 记录每个值的 source 与 retrieval date。对 practice 自身按其结果调参的 Development 成绩属于 in-sample；Development 为练习、不进入 Final 排名，所以此情形没有 sanction，但须在 provenance 中明确列出 practice units 作为例外。[#24 初次正式答复](https://github.com/Agenthon-2026/track4-analysis-public/issues/24#issuecomment-6001199755)

随后 **2026-10-07 01:48:40 UTC（香港 09:48）**明确：该许可适用于 **every Final task**，不必再依据各 Final cutoff 与 practice 首次发布日期的先后关系缩小这一许可。条件仍是首次发布值、逐值来源与取回日期，以及在 `ARTIFACT_PROVENANCE.md` 命名 practice units 的 in-sample exception。[#24 最终范围澄清](https://github.com/Agenthon-2026/track4-analysis-public/issues/24#issuecomment-6029140058)

准确边界：这是对上述公开 practice 常数和设计选择的明示例外，不把一般外部数据 cutoff 规则一并取消，也没有批准 task-answer lookup、私有/held-out Final 材料、额外模型或外部 inference corpus。对拟合完整预测器等超出该答复明确案例的用途，不把 constants/design choices 自动扩大解释为全面许可。practice 仍是格式示例而非 held-out 代表样本，in-sample 表现不证明 Final 泛化。官方初次答复称 `ten practice units`，本地公开目录计数另含 EXAMPLE；该措辞不提供隐藏题数量，也不能用来扩大未指明材料的权限。

本地研究可以独立重建已公开历史值并记录来源；这些值不是官方私有 outcome 或 naive 文件。主办方没有提供或推荐用于校准的 labeled benchmark；一般外部拟合/校准仍由参赛者自行取得合法、许可允许且符合 cutoff 的资料。本地对比不能精确复现官方 private naive anchor。[#23 官方答复，2026-10-04 22:29:38 UTC（香港 10 月 5 日 06:29）](https://github.com/Agenthon-2026/track4-analysis-public/issues/23#issuecomment-5985154828)

公开来源定位与原始全文快照hash保存在 [2026-10-07 官方澄清证据](evidence/official-clarifications-summary-20261007.json)，包含 UTC 时间、comment URL 与只读取回命令，全文留本地。

## 5. 推理阶段的冻结语料边界

正式评测只读取该任务提供的输入和官方冻结 corpus。离线训练可以形成合法参数，但不能把外部文档放进镜像后作为该题证据读入/引用；不能动态抓网页、行情、实时宏观版本、SEC 新 filing，也不能用访问 House 的线路抓数据。[来源：训练政策的 evaluation 边界](https://github.com/Agenthon-2026/track4-analysis-public/blob/458bc07efc05983de342ccb371e2b3cd793d621f/docs/TRAINING-POLICY.md)、[本地 asset 边界](https://github.com/Agenthon-2026/track4-analysis-public/blob/458bc07efc05983de342ccb371e2b3cd793d621f/docs/ARTIFACT-POLICY.md)

语料本身由官方 checksum manifest 定义；参与者不改写语料或把未经声明的文件当作同等证据。检索索引应在 `/input/corpus` 的实际官方资料上建立或匹配，保留原始 doc ID、日期、实体/shared 归属、原文 Unicode offsets。`corpus_ref` 或检索相似度不能覆盖这些引用资格。[来源：可信语料解析与声明规则](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/corpus.py)

## 6. 必须准备的 provenance 记录与 descriptor 披露

与镜像构建源码一起保存 `ARTIFACT_PROVENANCE.md`，供 organizer verification 查阅。每个 learned artifact 至少记录：

若常数或设计选择受公开 practice 历史结果影响，即使没有 learned weights，也须按 4.1 记录每个首次发布值的 source、retrieval date、所涉 practice unit，以及 practice 自身的 in-sample exception；不能只披露神经/learned 模型。[#24，2026-10-07 最终澄清](https://github.com/Agenthon-2026/track4-analysis-public/issues/24#issuecomment-6029140058)

| 内容 | 记录要求 |
|---|---|
| artifact 身份 | 模型/校准器名称、用途、不可变 revision 或 checksum |
| 数据来源 | source、dataset version、取得方法；不放凭证 |
| 数据许可 | 实际 license / terms、允许的训练用途 |
| 可获得时间 | feature 与 label 首次公开日期；区分 observation date / revision date |
| 分阶段数据 | 分开列 fitting/adaptation、selection、calibration 使用的数据与版本 |
| cutoff 适用范围 | 哪些题/哪些 cutoff 可以使用；为何每个阶段均满足边界 |
| 输出与资源 | artifact 的打包位置、构建版本及资源开销；不把这当新增资源申请 |

实际 learned local model 放在现有 `models[]` 条目里，`access: "local"`，保留 descriptor 支持的五字段：`name`、`version`、`training_cutoff`、`access`、`revision`。House 有实际使用时也要披露。纯代码和静态资产写进 provenance 文档，不虚构模型条目；没有加载模型或调用 endpoint 时，`models: []` 是有效的明确披露。[来源：artifact 披露](https://github.com/Agenthon-2026/track4-analysis-public/blob/458bc07efc05983de342ccb371e2b3cd793d621f/docs/ARTIFACT-POLICY.md)、[descriptor 模型字段](https://github.com/Agenthon-2026/Agenthon2026-public/blob/50fb2dc2b39c70f4cf81fcd269943782eddfaed0/starter-packs/track4/SUBMISSION-DESCRIPTOR.md)

## 7. 数据与代码 license：逐文件核对，不能一概而论

T4 的 `DATA-LICENSE.md` 记录 repository 默认 MIT，但明确 per-file manifest `license` 优先；商业 vendor 数据不因此得到许可。descriptor `license` 是参赛者自己作品的 OSI-approved license，不是官方 task data 的 license。[来源：DATA-LICENSE](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/DATA-LICENSE.md)、[descriptor license 的含义](https://github.com/Agenthon-2026/Agenthon2026-public/blob/50fb2dc2b39c70f4cf81fcd269943782eddfaed0/starter-packs/track4/SUBMISSION-DESCRIPTOR.md)

当前官方资料存在值得保留的冲突：`THIRD-PARTY-NOTICES.md` 对 organizer curation / labels / questions 仍描述为 CC BY-NC 4.0，还把 SEC EDGAR 与政府发布一起概括为 public domain；较新的 descriptor 指南区分「政府发布可属公共领域」与「SEC filings 是公开记录，申报者并未额外授予版权许可且保留自身权利」。因此不能把「网站公开」等同于「任意再分发/商用」，也不能从 repository 顶层 MIT 推出所有引用文档同为 MIT。[来源：第三方说明中的旧概括](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/THIRD-PARTY-NOTICES.md)、[较具体的提交指南](https://github.com/Agenthon-2026/Agenthon2026-public/blob/50fb2dc2b39c70f4cf81fcd269943782eddfaed0/starter-packs/track4/SUBMISSION-DESCRIPTOR.md)

执行原则：参赛训练/使用先看每个数据 source 与 manifest `license`，第三方组件保留自身条款；若计划再分发且逐文件条款与官方说明仍不一致，把确切文件和用途提交主办方澄清后再决定。官方提交指南同时明确不要把 task data vendor 进参赛镜像，应使用 evaluation 挂载的数据。

NLI judge 的 checkpoint、训练数据和参赛者提交模型是不同许可对象。官方 notes 记录 DeBERTa ensemble 两个成员权重分别有 Apache-2.0 与 MIT 等条款，训练集另有自己的许可；这份说明不能作为参赛镜像打包额外 checkpoint 的比赛批准。不要因为本地验证脚本能下载 judge 权重就把它自动当作获准的 participant reranker。[来源：第三方 model notices](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/THIRD-PARTY-NOTICES.md)、[额外神经checkpoint的唯一例外与禁止范围](https://github.com/Agenthon-2026/track4-analysis-public/blob/458bc07efc05983de342ccb371e2b3cd793d621f/docs/ARTIFACT-POLICY.md)

## 8. 方案评审与打包前的最小检查

1. 列出所有代码、静态资源、learned parameters 与 checkpoints，逐项映射到允许矩阵；神经资产须符合唯一例外并保存准确revision/checksum。
2. 对每个 learned artifact 核对 fitting / selection / calibration 数据的 first availability 与目标 cutoff，不只核对 observation 日期；若使用 4.1 的 practice 常数/设计例外，逐值记录首次发布版本、source、retrieval date 和 practice in-sample exception。
3. 核对数据、组件及模型实际许可，保留版本和来源；遇上节冲突不作 blanket MIT / public domain 声明。
4. 更新 `ARTIFACT_PROVENANCE.md` 和现有 `models[]`；纯代码无需 fictitious 模型行。
5. 检查镜像没有外部 inference corpus、答案 lookup、额外 LLM/adapter 或不在唯一例外内的checkpoint。
6. 确认正式 inference 只用 task / 官方 corpus、House 调用只走注入 endpoint、无 vendor tools 或数据 fetch。
7. 修改 descriptor 后按 toolkit 正式方法重新 seal / pack；provenance 文档不自行塞进 ZIP。

本轮只完成政策、schema、源码和样例的静态核对；未训练模型、未安装依赖、未下载 checkpoint、未构建/运行参赛镜像，没有额外神经checkpoint审批路线。这些执行验证应由后续实现 Phase 记录结果，不能根据本份规则研究将其标为已完成。
