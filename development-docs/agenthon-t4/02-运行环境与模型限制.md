## 2. 模型访问与网络：硬性边界

### 2.1 唯一模型路径

| 约束 | 内容 | 来源 |
|---|---|---|
| T4 category | `submission.json` 使用 `category: "api"`，模型免费通过主办方 House route 调用 | T4-CLI：Submission categories |
| BYO 取消 | 2026-09-18 起，不提供自带模型、in-image neural weights、LoRA/adapter 或自建 serving 路线；`byo-small` / `byo-large` 被 toolkit 拒绝，绕过打包后上传也 held 不运行 | T4-CLI；RUNTIME：Execution clocks |
| 通用互联网 | 评测不开放；只能走主办方 audited proxy 至注入的 House endpoint | T4-CLI：Network modes |
| 第三方 API | OpenAI、Anthropic、Gemini 等外部 provider API 不可访问；自带 key 不产生可达路径 | T4-CLI：Network modes |
| runtime 下载 | 不允许依赖外部安装、下载包、获取额外数据；依赖和允许的 artifact 必须构建时放入镜像 | RUNTIME：GPU and network access；IMAGE |
| vendor-side tools | 每个 API call 禁用 provider 的 web search、code execution、retrieval 等 server-side tools | T4-CLI：Rules for model-API use |
| 本地 artifact | 允许的 non-neural 数值模型、校准参数和 corpus-only retrieval artifact 仍需遵守 T4 artifact/training policy；GPU 存在不授权新 neural 模型 | T4-CLI；[固定 ARTIFACT-POLICY](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/docs/ARTIFACT-POLICY.md) |

网络模式只提供 `restricted` 与 `none`。T4 使用 restricted；本地无评测网络的 smoke 可能使用 none。网络不可用时 agent 应降级并尽量输出合法 `answer.json`，不能因此调用外部 API。来源：T4-CLI。

### 2.2 必须使用的环境变量与请求形状

| 变量 / 字段 | 含义及约束 |
|---|---|
| `MODEL_ENDPOINT` | 仅 origin：`scheme://host:port`，不含 API path；保持注入的 scheme，不写死地址 |
| 请求 path | **`POST $MODEL_ENDPOINT/v1/chat/completions`**；缺 `/v1` 的 `/chat/completions` 被拒绝为 HTTP 403 |
| `MODEL_NAME` | 每次 request 的 `model` 字段，直接用注入值；报告的 route alias 为 `house`，不替代 descriptor 中的模型身份 |
| `MODEL_TOKEN` | 每 unit bearer；每次加 `Authorization: Bearer $MODEL_TOKEN`，缺失会 HTTP 401 |
| `http_proxy` / `https_proxy`、大写版本 | 含每 unit 代理登录的 audited proxy；保持注入值，标准 HTTP client/SDK 通常自动读取 |
| `NO_PROXY` | 主办方注入的绕过 proxy 规则，保持环境约定 |
| `QFBENCH_NETWORK` | T4 official 为 `restricted`；本地 fallback 可为 `none` |

仅 `POST /v1/chat/completions` 被 admit，其他 method/path 被拒绝。403 / 401 是 admission 前拒绝，**不消费请求次数**。不要将 endpoint origin 直接当作不带 `/v1` 的 OpenAI `base_url`。来源：HOUSE：Calling the House route；T4-CLI：Container environment contract。

调用形状示例，只引用注入变量，不包含任何真实凭证：

```python
import os
from openai import OpenAI

client = OpenAI(
    base_url=os.environ["MODEL_ENDPOINT"].rstrip("/") + "/v1",
    api_key=os.environ["MODEL_TOKEN"],
)
response = client.chat.completions.create(
    model=os.environ["MODEL_NAME"],
    messages=[{"role": "user", "content": "任务上下文与合法证据"}],
    max_tokens=1024,
)
```

示例只演示协议；重试、timeout、seed、temperature、预算和异常降级必须在实际实现时明确配置与验证。

## 3. House 请求预算：按 admission 计次

| 规则 | 已公布值 / 行为 | 分类 |
|---|---|---|
| 每 unit 请求 | **最多 25 次 admitted generation requests** | 硬性额度，RUNTIME：House request allowance |
| 每 request 输出 | **最多 4,000 output tokens** | 硬性额度，同上 |
| 未传 output limit | route 使用 4,000 | 同上 |
| 请求大于 4,000 | route 下调至 4,000 | 同上 |
| 请求有效且小于 4,000 | 保留较小值 | 同上 |
| 多生成候选 | 请求 multiple generated alternatives 被拒绝 | 同上 |
| 计次时刻 | admit 后、forward 上游前即消费一次 | 同上 |
| 上游错误 / 丢响应 | admission 后发生错误、连接故障或 response 丢失，不退款 | 同上 |
| SDK / 自己重试 | 每次重新 admission 都是新请求，内容相同也会再次计数 | 同上 |
| admission 前拒绝 | invalid request 不计次；401/403 例子见上一节 | HOUSE 与 RUNTIME |
| prompt 与 context | 单次 prompt 加 output allowance 必须装入服务窗口；超窗在 admission 前拒绝，不计次 | [官网 FAQ：House allowance](https://www.agenthon.net/guides/faq/) |
| 累计 token allowance | **没有每 unit token 额度**；旧 `1,000,000 input + 100,000 output` 已撤销且没有替代值 | RUNTIME 与 T4-CLI |

**建议**：程序维护本地尝试账本，区分“发送尝试 / admit 后可能被收费 / 收到结果”，保留可用请求余量；把 SDK 自动重试计入设计，设置 timeout 与有限重试。官方 route 的 accounting 是权威，本地计数不能复原服务端未返回的 admission 状态。

**待确认**：实际 serving context window 的部署值，以及 thinking 输出如何在服务的 `usage`/输出 cap 中展示，公开 HOUSE 文档未作精确承诺。不能把 tokenizer 长度 metadata 当作可提交 prompt 的额度。

## 4. 模型身份、披露与推理控制

### 4.1 已批准 descriptor 行

所有五个字段均必须存在；不要估算训练 cutoff，也不要把发布日期写成训练日期。修改 descriptor 后用 toolkit 重封 digest 并重新打包。来源：HOUSE：Descriptor disclosure。

```json
{
  "name": "nvidia/nemotron-3-super-120b-a12b",
  "version": "rl-030326-fp8",
  "revision": "rl-030326-fp8",
  "training_cutoff": "unpublished",
  "access": "api"
}
```

`unpublished` 表示官方没有发布训练截止日。general-purpose pretraining例外适用于批准House revision及当前政策允许的NeMo Retriever embedding models；参赛者 tuning、selection、calibration、外部训练数据和自带 artifact 的 cutoff 仍约束。它不授权 BYO 或 adapter。[HOUSE](https://github.com/Agenthon-2026/Agenthon2026-public/blob/50fb2dc2b39c70f4cf81fcd269943782eddfaed0/docs/HOUSE-MODEL.md)、[T4 TRAINING-POLICY](https://github.com/Agenthon-2026/track4-analysis-public/blob/458bc07efc05983de342ccb371e2b3cd793d621f/docs/TRAINING-POLICY.md)。

### 4.2 Development 已报告的控制与 metadata

| 项目 | 已报告状态 | 不能推断的内容 |
|---|---|---|
| thinking | 默认开启 | 不保证不同 serving stack 的输出一致 |
| low-effort reasoning | 默认关闭 | 传 `low_effort` 的实际行为未经本指南验证 |
| 关闭 thinking | request body `chat_template_kwargs: {"enable_thinking": false}`；OpenAI client 放 `extra_body` | 不改变 model identity 或请求/输出预算 |
| 旧 system instruction | 不采用 `detailed thinking on/off` 控制，使用上述 API 参数 | 不能认为 system prompt 文字可靠切换模板 |
| `reasoning_budget` | route 会透传 `chat_template_kwargs` 内参数及 top-level 值 | 官方未测试实际效果，不构成预算豁免 |
| model/tokenizer snapshot | `rl-030326-fp8` | revision label 不是文件 cryptographic hash |
| architecture | `nemotron_h` / `NemotronHForCausalLM` | 是 operator 报告的 artifact metadata |
| Transformers metadata | `4.57.6` | 不是独立测得的 runtime package version |
| tokenizer maximum-length metadata | `262144` | **不是已承诺 serving context window** |
| vocabulary / tokenizer | `131072` / `PreTrainedTokenizerFast`；`add_bos_token=false` | 不改变已发布额度 |

以上来源：HOUSE：Development thinking controls / Reported model and tokenizer metadata。model/tokenizer metadata 来自主办方 operator 的只读报告，文档注明未独立复现。本项目也没有独立验证。

官方另报告服务容器 digest，该 digest 与参赛者镜像 digest、模型权重 hash 分别是不同概念；参赛 descriptor 的 `image` 必须填写自己的镜像。服务容器身份见 HOUSE：Serving container identity，不将服务容器引用写作本项目提交镜像。

temperature/seed 在 API 支持时固定；版本和 artifact 固定，保留复现配置。官方对 T4 rerun 作统计验证，不能以一次本地输出完全相同作为全部复现条件。来源：T4-CLI：Rules for model-API use。

## 6. 时钟：已公布机制与待部署 House 变更

### 6.1 Development 已公布执行时间

| 时钟 | 计算范围 | 直接影响 |
|---|---|---|
| per-unit container clock | container 创建、必要时 image pull、执行 | agent 得不到完整 600 秒纯计算时间；House 绝对 deadline 还可能缩短 |
| ingestion-stage clock | **43,200 秒 / 12 小时**，顺序运行所有 units | 不是每 unit 12 小时；晚到 unit 只能用剩余 stage 时间 |
| queue waiting | 在上述 stage clocks 外 | 不应把 queue 等待和 container runtime 混为一个时钟 |
| scoring | 单独 program stage 和自己的 platform clock | 12 小时不覆盖主办方所有 end-to-end 步骤 |
| cleanup | 另有有界 grace | 不是额外 agent 计算时间 |

来源：RUNTIME：Execution clocks；T4-CLI 开头。镜像过大、registry 慢、首次 kernel/cache 初始化均压缩实际执行余量。

### 6.2 已发布设计，明确仍 pending deployment and verification

以下是 **计划中的 execution-relative House timing release**，截至固定 main 文档仍不代表 live availability：

1. 每 House unit 只 activation 一次，时点为**主办方开始该 unit 执行 setup**，不是参赛者第一次 generation call。
2. 排队与更早 units 不消费该 unit 的 House window；activation 后 setup/provisioning、container creation、image pull 与执行消费窗口。
3. 固定 end time 是 `min(activation + card container ceiling 或 launcher fallback, 实际 ingestion stage end)`。stage clock 从真实平台 ingestion stage 开始；早前 units 消费共享 stage 时间，因此晚 unit 未必享有完整 ceiling。
4. 同 allocation restart/retry 不续窗口、不重置 request counters。
5. bearer credential 从签发起最多 **7,200 秒**，且绝不超过固定 unit end；签发 credential 不延长窗口。
6. 变更不新增 container time、stage time、25 次请求额度或其他计算资源。

来源：RUNTIME：Execution clocks；T4-HW：Planned timing and access；T4-CLI。**项目处理**：按更紧的 card/stage/runtime deadline 做超时预算；正式提交前回读部署公告，不能把 7,200 秒 credential TTL 当成 T4 600 秒之外的运行时间。

## 7. T4 命令和文件系统

### 硬性接口

```text
analyze --task /input/task.json --corpus /input/corpus/ --out /output/answer.json
```

- `analyze` 是 image 后的第一个 command/argument：无 `ENTRYPOINT` 时它须在 `PATH` 且可执行；有 `ENTRYPOINT` 时程序须消费这个 leading positional。
- 镜像设置 `LABEL qfbench2.interface_version="2.0"`，与 descriptor 对齐。
- T4 必须写 **`/output/answer.json`**，退出码 **0**；写入 `/app/output` 或 `/output/subdir/answer.json` 不是有效答案位置。
- JSON 使用 UTF-8、无 BOM；答案字段与 schema/roster/embargo/citation 等规则另需校验。schema 检查不能代替完整 T4 checker。

来源：T4-CLI、T4-README、T4-HW：Your image。

### Development 常见启动失败与建议

- uid 65534 可能没有 user entry 或可用 home；`HOME` 未设置或指向 `/nonexistent`。Hugging Face、Numba、Matplotlib、pip/tool state 等不能写 `/root`、`/app` 或自己的只读安装目录。
- 将需要的 cache 用组件专用变量（如 `HF_HOME`、`NUMBA_CACHE_DIR`、`MPLCONFIGDIR`、`XDG_CACHE_HOME`）定向到受控的 `/tmp`，或构建时做好只读 artifact；不能超过 64 MiB tmpfs。
- `/tmp` 为 `noexec`，运行中解压/编译到该目录的程序不能执行；预先把 binary 编进镜像。
- 显式限制线程池/loader 并发，避免 256 PIDs 和 1,024 file descriptors 上限。
- 仅答案及必要少量附属文件放 `/output`；缓存、调试日志也占树 cap 并接受全树扫描。

来源：RUNTIME：Run it locally the way the platform runs it。

## 8. 输出树接受规则与失败归因

完整 `/output` 在进程退出后检查。即使 `answer.json` 有效，其他文件使整个树被拒绝仍会失败。来源：T4-README 的平台 output rules；核对 [toolkit sanitize.py](https://github.com/Agenthon-2026/Agenthon2026-public/blob/50fb2dc2b39c70f4cf81fcd269943782eddfaed0/common/qfbench2_common/sanitize.py) 与 [artifact_tree.py](https://github.com/Agenthon-2026/Agenthon2026-public/blob/50fb2dc2b39c70f4cf81fcd269943782eddfaed0/common/qfbench2_common/contracts/artifact_tree.py)。

| 拒绝条件 | 已公布边界 / 项目要求 |
|---|---|
| 数量 | 超过 **256 文件**，或文件+目录超过 **4,096 节点** |
| 深度 | 目录嵌套 **8 层或以上**；项目保持 flat output |
| 类型 | symbolic link、hard link、特殊文件；仅正常单 link regular files 与正常目录 |
| mode | 文件含 setuid、setgid 或 sticky bit |
| 稀疏文件 | apparent size / allocated disk size 超过 **64 倍** |
| 名称 | 大小写或 Unicode 形式碰撞；非 UTF-8/非 NFC；含 backslash/control character；顶层 drive-style `C:` 等 |
| 可读性 | 不可读文件/目录可能使 sanitizer fail closed；确保 evaluator 能读 |
| 总内容 | 没有任何文件，或总量超过 **64 MiB**；单文件也最多 **64 MiB** |
| leakage | Final 的 output 任意位置出现 canary 即 contamination；扫描不是只看 `answer.json` 或 allowlisted extension |

**重要差别**：共享 `TreeLimits` 类默认 `max_total_bytes` 为 256 MiB，平台/赛道输出限制更紧为 **64 MiB**；不能从 class default 推导参赛额度。上述 output-tree 大小 cap 已由 T4 README 明确同时适用于 Final。

| 运行结果 | unit 对外 failure code / 处理 |
|---|---|
| process 退出 0，但 tree 不被接受 | T4 README 公布为 `no_output` |
| process 非 0 退出 | `container_crashed`，即使树中已有文件 |
| 达到 time limit | `resource_timeout` |
| 内存 kill | `resource_oom` |
| Final canary hit | contamination，unit 不作为成功输出 |

这些 unit failures 保留 roster 分母，取 T4 最差值；不能与 CodaBench submission 状态 `Failed` 的次数例外混淆。计次与最差值见 01；字段级评测与 reasons/claims 见后续评分文档。

## 9. 镜像拉取、layer 与权限

### 硬性 / 支持路线

| 项目 | 要求 | 来源 |
|---|---|---|
| 平台 | `linux/amd64`；ARM-only 镜像无法运行 | IMAGE；[官网 FAQ](https://www.agenthon.net/guides/faq/) |
| immutable identity | registry/repository + `sha256` digest；floating tag 在拉取前被拒绝 | IMAGE；[官网 submission-format](https://www.agenthon.net/guides/submission-format/) |
| public route | digest 与 layers 能在无工作站登录凭证时匿名拉取 | IMAGE；T4-HW |
| public visibility | 他人也能下载 public image 的全部文件；repo public 不证明 container package public | IMAGE |
| private mirror | 上传前取得主办方确认的 handoff 和精确 image reference；`organizer_mirror` 字段本身不传 image、不授 registry 权限 | IMAGE |
| credential | 不在 descriptor/proof/ZIP/image 中嵌 registry password、个人 API key 或 Team Key | IMAGE；官网 Rules §6 |
| rebuild | 改镜像后 push、新 digest、repack/reseal descriptor；不复用旧 proof | IMAGE |
| dependency | 构建阶段纳入允许组件；runtime 无网络安装 | IMAGE / RUNTIME |

### Apple Silicon / Mac layers

Mac ARM 默认 `docker build` 可能产出 arm64，需要明确 target `linux/amd64`。官网 FAQ 特别指出带 `com.apple.provenance` 的文件 layer 可能在 evaluator 解包时失败、程序尚未启动；BuildKit 0.22+ 的正常 `COPY` 会去除这类属性，如从 Mac tarball 加 layer 使用 `tar --no-xattrs`，不能只依赖 `xattr -cr`。来源：[官网 FAQ：What do we actually submit?](https://www.agenthon.net/guides/faq/)。

**建议**：在 credential-free 环境拉取 exact digest 的 manifest 与所有 layers，再验证架构、label、entrypoint 和实际运行；只拿到 manifest HTTP 200 不证明完整可拉取或可执行。压缩 image 可减少计入 unit clock 的 pull 时间。

T4 README 的已公布镜像大小建议为 **≤15 GB**，**>20 GB 可能被拒绝**；原文明确这不是已验证自动执行的 size quota。image-layer limit 是另一种资源，公开固定资料没有给出具体层数，“最多 20 layers”未确认。来源：[固定 T4 README：Runtime constraints](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/README.md#runtime-constraints)。

**待官方确认**：自动执行的 image-download size / layer-count quota 未给出；不能把 `/output` 64 MiB 或 writable-layer 1 GiB 当镜像尺寸限制。私有镜像 handoff 未确认前，不能自行认定 private route 已可用，也不以公开机密镜像绕过失败。

## 10. 本地执行验证规格：建议采用平台约束

官方 starter 的简单 `docker run` 只证明启动/输出，不施加全部 sandbox 设置。正式开发时至少用一个 unit 验证下列配置；本轮未执行该命令：

```bash
docker run --rm \
  --read-only --user 65534:65534 --cap-drop=ALL \
  --security-opt no-new-privileges \
  --tmpfs /tmp:rw,noexec,nosuid,nodev,size=64m \
  --pids-limit 256 --ulimit nofile=1024:1024 --ulimit nproc=256:256 \
  --ulimit fsize=67108864:67108864 \
  --cpus 16 --memory 128g --memory-swap 128g \
  --network=none \
  -v "$PWD/units/<unit>":/input:ro \
  -v "$PWD/out":/output \
  -e QFBENCH_SEED=0 -e QFBENCH_NETWORK=none \
  <image>@sha256:<digest> \
  analyze --task /input/task.json --corpus /input/corpus/ --out /output/answer.json
```

运行前让宿主 `out/` 对 uid 65534 可写，检查输出树与答案；T4 不加 `/app/output` mount。上述为离线 filesystem/resource smoke；GPU、House proxy、600 秒 clock、12 小时 stage、调用 admission 与远端计费需要各自独立验证，不能因为此命令通过就宣称 official run 通过。`fsize` 以 byte 配置，实际 Docker/OS ulimit 行为在目标开发主机确认。

本地验证 House code path 可用自己的 OpenAI-compatible mock/server，仅复刻 `$MODEL_ENDPOINT/v1/chat/completions` + bearer 形状；本地模型不进入提交 image，也不据其质量代替 House 模型评测。主办方代理环境本地通常不存在，client 应读取环境而不写死 proxy。来源：RUNTIME：Run it locally the way the platform runs it。
