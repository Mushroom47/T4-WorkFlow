# T4 输入、输出与引用契约

本文件把 T4 的输入、逐实体预测、证据引用和可选推理理由整理成实现时可核对的契约。研究日期为 2026-10-07；T4 官方仓库固定到 `1c744e1d6725340643a533f436517d72b53ca0e1`，共享 toolkit 固定到 `v2.5.1` / `50fb2dc2b39c70f4cf81fcd269943782eddfaed0`。当前 T4 scorer 为 `5.2.2`。本文区分「schema 必填」「评分器追加要求」「可选」「工程建议」，不能只通过 JSON Schema 就认定答案可评分。

## 1. 最小执行与输入布局

官方以如下命令调用参赛镜像：

```text
analyze --task /input/task.json --corpus /input/corpus/ --out /output/answer.json
```

`analyze` 是镜像名后的首个参数，必须由 `ENTRYPOINT` 接收，或在 `PATH` 上存在可执行程序。`/input` 挂载的是整个 unit 目录，且只读；结果写到 `/output/answer.json`，成功退出码为 `0`。命令、文件缺失或异常退出会使该 unit 失败。容器、网络、超时及镜像要求见本任务的运行与提交文档。[来源：当前 CLI](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md)

| 输入 | 用途 | 实现时需要保留的事实 |
|---|---|---|
| `task.json` | 参赛者可见任务与实体表 | `task_id`、嵌套 `target`、`prompt`、`cutoff_date`、`resolution_date`、`interval_level`、`entities` |
| `card.toml` | unit 的评分与运行参数 | `[scoring.params]`、`[environment]`、`[agent].timeout_sec`、`[embargo]`；资源以实际 card 为准 |
| unit 根目录 `manifest.json` | 官方文件清单、checksum、许可与归属 | `files[]`；引用只解析清单声明且 `role: "corpus"` 的文档 |
| `corpus/<doc_id>.json` | 冻结的证据文档 | 文本通常在 `text`；日期在 `doc_date`；不得从引用对象自报日期代替 |
| `corpus/manifest.json`（若有） | 语料目录自身的清单 | 不是可引用文档；不要假定每个 unit 都有此文件 |

根目录 checksum manifest 不是自由构造的 `documents[]` 文档索引。解析时应读取实际布局，不应只依赖文件名推测文档资格。[来源：unit 布局说明](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/docs/AUTHORING-GUIDE.md)、[可信语料解析实现](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/corpus.py)

## 2. 读题的顺序：对象、目标、期间、单位、方向

1. 从 `entities[]` 建立完整 `entity_id` roster。公司、发行人、期限、期货市场、CPI 分项和宏观序列都可能是实体，不能硬编码成股票 ticker。
2. 从 `target.type` 确认任务类型；输入不是扁平 `target_type`。读取 `target.name`、分类的 `target.labels` 和任务自身的 `label_assertions`，以题目定义解释标签。
3. 从 `prompt`、行内日期及 `cutoff_date` / `resolution_date` 识别预测窗口。同比、环比、季度、首次发布值、下一次修订、收盘到收盘和事件窗口不能互换。
4. 从 `prompt` 和每行 `unit` / `units` 确认输出量纲。`0.30` 个百分比单位与 `0.003` 的比例值相差 100 倍；basis points、percentage points、美元、百万美元、裸比率也不能混用。
5. 把方向和数值符号一致化：例如收益率变化的正号表示上升；若任务定义 rank 1 为最大净多头增幅，`point_forecast` 仍应是该增幅数值。

行内特征是 cutoff 前已知的信息，常包含上一期同类指标。它们不是未来真值；当前公开 unit 没有发布 resolved outcomes。分类题也可能要求给实际数值预测与区间，不能把「分类」等同于「只输出概率」。[来源：输入字段与输出约束](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/docs/AUTHORING-GUIDE.md)、[当前 CLI](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md)

## 3. 三种 `target.type` 与逐行字段

| `target.type` | 必须给出的主预测 | `point_forecast` 的含义 | `interval` | `rank` |
|---|---|---|---|---|
| `classification` | 有效 `label`，且属于任务声明的标签集合 | schema 可省略；若题目要求数值，则给题目量纲中的数值，不应统一解释为分类置信度 | 每行结构必填；有数值 truth 且 interval leg 生效时，区间须覆盖该数值目标 | 不需要 |
| `regression` | 有限数值 `point_forecast` | 目标本身的预测值 | 每行必填，与目标同单位 | 不需要 |
| `ranking` | 有限数值 `point_forecast` | 用来排序的**预测指标值**，例如净持仓变化占 open interest 的百分比 | 每行必填，围绕同一个指标值 | 可选；提供时必须每行都有，且组成 `1..n` 的完整排列；1 表示最高 |

排序分数读取 `point_forecast`，不读取 `rank` 或 `label`。把名次 1、2、3 写进 `point_forecast`，可能把「最高指标」的顺序倒置。即使纯标签题不计 interval leg，schema 仍要求 `interval`。当前 schema 把 `interval.level` 固定为 `0.90`，实现还要求它等于该 unit 的 interval level；`lo <= hi`，全部数字必须有限。[来源：输出 schema](https://github.com/Agenthon-2026/Agenthon2026-public/blob/50fb2dc2b39c70f4cf81fcd269943782eddfaed0/common/qfbench2_common/schemas/analysis.schema.json)、[roster 与数值验证实现](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/alignment.py)

## 4. `answer.json`：必填、可选和工程建议

| 位置 / 字段 | 级别 | 具体约束 |
|---|---|---|
| `task_id` | schema 必填，且有语义校验 | 字符串；原样复制当前任务 ID，不能指向其他题 |
| `entity_predictions` | schema 必填，且有 roster 校验 | 非空数组；所有任务实体恰好出现一次，不能缺失、增加、重复；行顺序可不同 |
| `schema_version` | 可选 | 若填写，使用当前任务支持的 schema generation；建议从任务复制，不硬编码旧模板 |
| `target_type` | 可选 | 若填写，只能是三个合法值且必须匹配任务/card；不确定时省略，比复制错误的 `classification` 安全 |
| 每行 `entity_id` | schema 必填 | 与 roster 中的字符串精确一致；不要改变大小写、拼写或 Unicode 规范形式 |
| 每行 `interval` | schema 必填，且有语义校验 | 对象必须含数值 `level`、`lo`、`hi`；`level: 0.90`、有限值、非倒置 |
| 每行 `claims` | schema 必填 | 至少一个 claim；每个 claim 同时含字符串 `doc_id`、非负整数 `span_start` / `span_end` 和字符串 `claim` |
| 每行 `label` | 按任务必填 | 分类题必须有非空有效标签；非分类题可省略 |
| 每行 `point_forecast` | 按任务必填 | regression/ranking 必填；classification 按实际 prompt 的数值要求填写；出现时必须有限 |
| 每行 `rank` | 可选但有完整性约束 | 一旦提供，就不能只给部分实体；完整整数排列 `1..n`，并且 schema 要求该行有 `point_forecast` |
| `submitted_reasons` | 可选但有严格 schema | 省略表示不提交理由；提供时必须是 1–3 个合法 reason，不能用空数组 |
| `evidence_trace` | 可选 | 字符串或字符串数组；不作为 reasoning 输入，不替代 claims / reasons |
| `notes` | 可选 | 对象；不参与评分，不把解释只放在这里 |

未知附加字段不等于得到评分器支持。尤其不能在 claim 内加入 `citations` 列表：5.2.2 只读取 claim 自己的单个 `doc_id` / offsets，该键的存在使该 claim 计为 false。顶层 `submitted_answer` 不会作为答案被 reasoning grader 读取。[来源：完整 schema](https://github.com/Agenthon-2026/Agenthon2026-public/blob/50fb2dc2b39c70f4cf81fcd269943782eddfaed0/common/qfbench2_common/schemas/analysis.schema.json)、[当前 CLI 的 claims 与 reasons 合同](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md)、[task_id 校验](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/scoring.py)

## 5. 引用必须定位到原始文本的 Unicode 字符位置

引用窗口是左闭右开 `[span_start, span_end)`，从 0 开始，等价于 Python 的 `text[span_start:span_end]`，正常引用满足 `0 <= start < end <= len(text)`。这里数的是 Python 字符串的 Unicode code points，不是 UTF-8 bytes，也不是 JavaScript 的 UTF-16 code units。中文、emoji、组合字符和换行都会暴露计数差异；实现应保留原始文本，索引时带回它的原始 offsets，输出前再切片确认。[来源：task 字符位置定义与实现](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/corpus.py)、[引用说明](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/docs/AUTHORING-GUIDE.md)

文档的常规引用文本是 JSON 解码后的 `text` 字符串，不是整个 JSON 文件或其序列化内容。共享 `_doc_text` 还支持原始字符串，或把 `spans[].text` 用单个空格连接；采用后一形态时 offsets 必须针对连接结果。不要对原文做 trim、空白折叠、Unicode 规范化、HTML 清洗或翻译之后仍沿用旧位置。JSON 转义符的原始字节数不参与字符计数。[来源：共享文本读取实现](https://github.com/Agenthon-2026/Agenthon2026-public/blob/50fb2dc2b39c70f4cf81fcd269943782eddfaed0/common/qfbench2_common/scoring/faithfulness.py)

`doc_id` 是 manifest 内文档的 ID，不是文件路径或 URL。当前解析器接受单一 ASCII 组件，正则为 `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`；不接受路径分隔符、路径穿越、绝对路径或未声明的 ID。仅有某文件存在于目录中，不能使其成为可解析的官方证据。[来源：可信语料解析器](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/corpus.py)

### 文档归属与日期

- claim 使用的 corpus 文档必须被 unit manifest 标注为当前实体的 `entity_ids` 成员，或 `shared: true`。文件名、文档自己的 ticker 字段或搜索命中不能代替 manifest 归属。
- `entity_ids: []` 意味着该文档不属于 roster 中任何实体；引用一个已标注为其他实体的文档使该 claim 计 false。整个 manifest 都未标注归属，或已标注的 manifest 漏掉当前被引用文档的归属，是 organizer fault，不计为参赛者错误；缺少归属也不能自动解释成共享文档。
- 引用文档的 `doc_date` 必须是有效的 `YYYY-MM-DD`，且不晚于任务 `cutoff_date`。日期缺失、格式错误、未知文档和 cutoff 后引用属于整题失败。
- 日期筛选应在检索和模型读证据之前完成，避免把后验资料用于推理之后再删引用。

[来源：归属、日期、解析检查](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/corpus.py)

### `doc_id: "task"` 的特殊规则

claims 可以引用任务给定的实体特征。其引用目标不是整个 `task.json` 文件，而是评分器构造的「task table」：

```python
lines = [
    json.dumps(row, ensure_ascii=False, separators=(", ", ": "))
    for row in task["entities"]
]
task_text = "\n".join(lines)  # 保持行顺序和键顺序；无末尾换行
```

引用位置针对这一完整字符串计算。一个 claim 的 slice 必须完全落在**本行实体**的单行范围内，不能跨行、引用另一实体或按紧凑 JSON 算 offsets。建议直接调用官方 `task_table_text(task)`，它返回 `(text, entity_id -> (start, end))`。`task` 特例只支持 claims；reason citations 仅解析 corpus，`"task"` 在 reason 中不会给 judge 证据。reason 需要的任务特征，应在 `premise` 里明确陈述。[来源：task_table_text 与归属检查](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/corpus.py)、[reason 合同](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md)

## 6. claim 是证据事实；推导写进 reason

每个 claim 只有一个文档的一个 span。两份文档的数字分成两个 claims；同一文档两段数字只有在同一个 span 覆盖两段且不超过 cap 时才能放在一个 claim。文本应陈述证据说了什么：例如收入、管理层指引或已发布利率；计算的变化量、比率、均值、推断路径放入 `submitted_reasons[].mechanism`。

当前确定性的 false 条件包括：错误实体、越界 span、空文本、超过 4,000 字符、超过 400 judge tokens、span 超过 8,000 字符、没有被该 span 携带的数字、只有证据/元信息的占位陈述、claim 内存在旧 `citations` 键。Final 还会做 NLI 矛盾检查；Development board 当前不做该 NLI 检查。因此 Development 无扣分不能证明 Final 的 claim 全部合格。[来源：5.2.2 claim 规则](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md)

数字校验读取整个已引用 span，不能依赖 span 外的上下文。等价单位表达可以匹配，例如 quarter-point 与 25 bps；按 scorer 的尺度规则精确匹配，不靠四舍五入。日期、期间、期间数量及标识符不视作财务数字；实体自身名称中的数字有豁免。等于自身**实际被评分**的点预测/区间端点、对应的 `±` 半宽和 interval level 有有限豁免，写出的涨跌方向仍须与符号一致；`rank` 不享受此豁免。工程上应优先选取短原文 quote，计算放 reason，避免靠边缘豁免构造 claim。[来源：完整数字与 claim 规则](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/docs/CONCEPTS.md)、[当前 CLI](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md)

## 7. `submitted_reasons` 的完整契约

理由是可选的顶层数组，提供时为 1–3 个对象。省略仅失去 reasoning bonus；`[]`、超过三个或缺必填字段属于 schema 错误，使整个答案无效。`claims`、`evidence_trace`、`notes` 不能代替该字段。[来源：schema](https://github.com/Agenthon-2026/Agenthon2026-public/blob/50fb2dc2b39c70f4cf81fcd269943782eddfaed0/common/qfbench2_common/schemas/analysis.schema.json)、[reason 合同](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md)

| reason 字段 | 必填 | 类型与用途 |
|---|---|---|
| `reason_id` | 是 | 字符串；建议唯一。judge 按位置重编号，不以自选 ID 加分 |
| `premise` | 是 | 字符串；有证据支撑的事实，依赖任务特征时明确写出 |
| `mechanism` | 是 | 字符串；解释事实怎样影响目标，可包含推导与计算 |
| `answer_implication` | 是 | 字符串；说明对已经提交的预测有什么含义，并明确实体 |
| `scope` | 否 | 对象，可含字符串数组 `entities`；不展示给 judge |
| `citations` | 否 | 数组，每个对象必须含字符串 `doc_id` 与非负整数 `span_start`、`span_end`；仅解析冻结 corpus |

reason 引用不能解析、过 cutoff 或越界时，该 passage 不给 judge，通常不使 analysis 整题失败；但负数 offsets、错误类型和缺字段仍是 schema 错误。reason 引用即使是 schema 合法也不保证 evidence_grounding。judge 读取 prompt、实体 ID/名称、单位声明的答案字段，以及 reason 的三段文字和成功解析的 evidence；不会读取 task table 所有特征、`scope`、raw citations、`claims` 或 `rank`。发布单位中的 regression/ranking 使用 `point_forecast` / `interval`；classification 使用 `label`，有 interval leg 时还使用 `interval`。发布单位没有声明 `label_probs`。[来源：reason grader 可见信息](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md)

### cap：字符数和 UTF-8 bytes 必须分开

| cap | 上限 | 超过后的结果 |
|---|---|---|
| 单个 reason citation 的 `span_end - span_start` | 8,000 字符 | 该 reason 不评判 |
| judge 实际读取的全体答案投影 | 3,000 bytes | 此 unit 的 reasoning 不评判 |
| 被评判 reasons 的投影总量 | 6,500 bytes | 不能放入的 reason 不评判，继续尝试后面的 reason |
| 被评判 reasons 的成功解析 passages 总量 | 46,500 bytes | 同上 |
| 三类输入合计 backstop | 56,000 bytes | 不裁剪内容；按 grader 规则处理 |

bytes 是 judge 投影后的 compact JSON 的 UTF-8 大小，包含 JSON 转义与包装开销，不等于字符数。中文通常每 code point 占 3 bytes；引号/换行等转义会增加大小；引用中的 URI masking 与自写 reason 的 URL masking 也影响计数。按提交顺序依次收纳，最强 reason 放前面。三个 reason 内容经 Unicode NFC、不可见格式字符移除、case folding、空白折叠后相同，则重复项不评判；只改 `reason_id` 没有用。[来源：caps 与重复处理](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md)

### deny list：reason 文字中不能夹入评分身份或文件路径指令

以下内容在 reason 自写文字中按不区分大小写的子串检查，命中会使该 unit 的 reasoning 为 0：

```text
leaderboard, canary, /home/, units/, reference/, outcome.json,
team_id, team name, participant_id, participant name,
submission_id, other submission
```

`mechanism` 和 `answer_implication` 始终检查。`premise` 只有在它完整为一份 corpus 文档的逐字 quote、URL masking 后至少三个词且可以在同份文档找到时，才可获得 quote 豁免；引用的 corpus 原文也有豁免。自行添词、短 token 或一两个词的 quote 不适用。URL 本身并非全部禁止，但写入的 URL 仍先接受 deny list 检查，再被 masking；无 scheme 的 `://` 以及 Unicode 伪装的禁止短语/URL 也有处理。工程上保持 reasons 内容为任务事实、机制和答案含义，把路径、身份与评分说明放到文档或日志。[来源：deny list 与 URI 处理](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md)、[本地 advisory checker](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/baselines/guardrails_example/citation_rail.py)

## 9. 输出前检查方法

建议在参与项目具备相应固定版本依赖后，对每个 unit 执行以下顺序；本轮研究没有安装依赖、运行参赛 Agent、调用模型或计分。

1. 验证 `answer.json` 是有效 JSON，禁止序列化 NaN / Inf；对照 toolkit 的 `analysis.schema.json` 验证。
2. 对齐完整 roster，确认 `task_id`、target type、分类标签、数值字段、区间及完整 rank permutation。
3. 每个 claim 先按 manifest 资格、文档日期和实体归属检查，再用原始文本执行 slice，确认左右边界、quoted text 和 length。
4. 调用 `check_claim_rules(answer, unit_dir)` 做评分器的确定性校验；调用 `check_submitted_reasons(answer, corpus, cutoff_date)` 检查 reason 形状、passage、caps、重复和 deny list。
5. 有本地官方 NLI judge 时再做 full faithfulness preview；没有 judge/tokenizer 时，明确缺少哪些检查，不把 advisory 或 smoke 的通过等同于正式分数。

下面是供后续实施使用的官方本地检查形式；先替换三个路径占位符。通过 `sys.path` 指向官方固定版本源码，避免误导入其他检出。`check_claim_rules` 需要该源码及已安装的 `qfbench2-common==2.5.1` 与其依赖；reason checker 本身使用标准库。自动 tokenizer 检查仅使用已有本地缓存，不会下载权重；缺 tokenizer 时报告 `claim_tokens_unchecked`，不能据此宣布 400-token cap 已通过。

```python
import json
import sys
from pathlib import Path

t4_repo = Path("<T4官方固定版本检出根目录>").resolve()
sys.path.insert(0, str(t4_repo))
from baselines.guardrails_example.citation_rail import (
    check_claim_rules, check_submitted_reasons, load_corpus,
)

unit_dir = str(Path("<unit目录>").resolve())
answer = json.load(open("<answer.json>", encoding="utf-8"))
task = json.load(open(f"{unit_dir}/task.json", encoding="utf-8"))
for finding in check_claim_rules(answer, unit_dir):
    print(finding)
corpus = load_corpus(f"{unit_dir}/corpus")
for finding in check_submitted_reasons(answer, corpus, task["cutoff_date"]):
    print(finding)
```

`unit_refused` 表示整题会被拒绝；claim false 的 findings 表示扣分风险；reason findings 必须区分 schema 错误、某条 reason 不评判、某个 passage 不可见和全题 reasoning 为 0。advisory checker 不是最终 authority。[来源：本地 checker 与 finding 定义](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/baselines/guardrails_example/citation_rail.py)

## 10. 容易误读的旧文案与整题失败

当前固定版本中 `docs/CATEGORIES.md` 仍含旧说法：输出 `target_type` 必须、NLI 对 prediction entailment / 80% 门槛，以及个别旧 failure 解释。`task.json.faithfulness_rubric` 也保留旧文案。现行 CLI、schema 和实现明确：`target_type` 可省略；faithfulness 对 claim 逐条 false/neutral 惩罚；legacy rubric 不读取。`CONCEPTS.md` 的部分早期概念段也有遗留说明，应以其更新后的 Faithfulness 节、现行 CLI 与评分实现核对。[来源：分类说明的历史段落](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/docs/CATEGORIES.md)、[当前权威 CLI](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md)

**硬性整题失败**包括输出缺失/格式不合法、task ID 错误、schema 错误、roster 不一致、目标类型冲突、主预测缺失/分类标签非法、数值非有限、区间缺字段/倒置/level 不符、rank 不完整，以及 claims 引用格式不合法、无法解析/未注明合法日期/超过 cutoff。不是只丢掉坏行，也不缩小 denominator；该 unit 的 analysis 得到 `W = 0.0`，在原 leaderboard 尺度显示 `-0.27`。单个 claim 错误实体或 span 越界在当前规则下通常是 false claim 扣分，不要与未知/未定日期文档导致的整题失败混淆。[来源：alignment](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/alignment.py)、[评分实现](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/scoring.py)、[CLI](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md)
