## 4. 团队、账号与报名证明

### 硬性规则

- 参加者至少 18 岁并达到所在地成年年龄，参赛必须合法；需自行取得必要的雇主或学校授权。每队 1–3 名注册成员，每人只能有一个身份、加入一个团队，指定 captain。组织者、评委及有私测特权访问者等受奖项利益冲突限制。队伍变更需主办方批准，通常应在 Final 前完成。[Rules §4](https://www.agenthon.net/rules/)
- 一队统一使用 **一个指定 CodaBench 账号**上传。首个有效 team proof 将该账号绑定至 agenthon.net 队伍，其他成员继续参与开发但不另用账号上传。[固定 T4 CLI：How an upload is made](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md#how-an-upload-is-made)、[toolkit TEAM-CLAIM](https://github.com/Agenthon-2026/Agenthon2026-public/blob/50fb2dc2b39c70f4cf81fcd269943782eddfaed0/starter-packs/track4/TEAM-CLAIM.md)
- 网站注册、CodaBench 入场/审批、ZIP 中的队伍证明是不同步骤。邮箱相同不能替代证明。Team Number 是网站编号，`team_id` 是 toolkit 推导的别名；不得保留示例队伍的 ID。ZIP 包含 `submission.json` 与 `team-claim.json`，不包含 Team Key、镜像层或 registry 凭证。[官方 What You Submit](https://www.agenthon.net/guides/submission-format/)

### 建议与待确认

- 提交前确认实际成员、captain、唯一绑定账号和剩余次数；不要用另一个账号修复绑定问题。
- 本次未核实自己的报名、Team Number、账号绑定或上传开放状态。具体 CodaBench 入口来自登录后的 agenthon.net 公告，不从公共页面猜测私有比赛链接。
- Team Key 和打包后的 proof 都需私密保存；文档、Git、Linear、日志只记录变量名、状态和必要的 submission ID。支持沟通仅提供 ID 与可见状态，不附任何密钥或 proof。[官方 FAQ](https://www.agenthon.net/guides/faq/)

## 5. T4 Development 上传次数

| 项目 | 已公布条件 | 来源 |
|---|---|---|
| 每日上传 | 每队 T4 **5 次/日** | [固定 T4 CLI：Development submission limits](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md#development-submission-limits) |
| Development 总上传 | 每队 T4 **20 次** | 同上 |
| Held / cancelled | 即使没有分数也消耗上传次数；重传替代包再消耗一次 | [K-runtime：Submission limits](https://github.com/Agenthon-2026/Agenthon2026-public/blob/50fb2dc2b39c70f4cf81fcd269943782eddfaed0/docs/DEVELOPMENT-RUNTIME.md#submission-limits-at-the-development-opening) |
| 本地检查 / 打包 | 不消耗上传次数 | 同上 |
| 平台 `Failed` 状态 | CLI/runtime 明说不消耗 attempt，解释为平台 daily count 将其排除 | 同上及固定 T4 CLI |

**不要混淆三类失败**：CodaBench submission 状态 `Failed`；已经完成评测但某个 unit 失败；上传被 held/cancelled。只有第一类有上述平台次数例外，unit 失败不是免费重交机会。

**待官方确认**：每日次数以哪一个时区、何时重置，公开文件未给出精确定义；`Failed` 对总数 20 的后台统计是否与 daily count 一致，仍需从账号计数或主办方确认。不要据此安排无限失败重传。上传 held 或卡住时先用 submission ID 联系主办方，避免反复上传消耗剩余次数。

## 6. Final、验证与排名

### 硬性规则 / 已公布协议

- T4 **每队仅一个 final submission，不允许 resubmission**。Final 与主办方 verification 是同一阶段，不存在参赛者再交第二个 verification 包的机会。[官方 FAQ](https://www.agenthon.net/guides/faq/)、[固定 T4 CLI：Development submission limits](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/SUBMISSION_CLI.md#development-submission-limits)
- 最终程序在指定 sandbox 内全自动运行；主办方在 sealed held-out units 上评测并重跑领先方案。Development 分数是 provisional，不能视为 Final 成绩承诺。Final 输出、日志与 score 文件保持隐藏。[Rules §§6–8](https://www.agenthon.net/rules/)、[官网 Final + Verification](https://www.agenthon.net/#timeline)
- 已公布技术协议采用 **Final 相同 ranking score 时，较早上传者优先**。通用 Rules §7 的默认规则是“没有发布赛道 tie-breaker 才保留并列”，本项目使用已发布的具体 tie-breaker。[K-runtime：Competition schedule](https://github.com/Agenthon-2026/Agenthon2026-public/blob/50fb2dc2b39c70f4cf81fcd269943782eddfaed0/docs/DEVELOPMENT-RUNTIME.md#competition-schedule)、[Rules §§7、12](https://www.agenthon.net/rules/)
- 获奖候选人按要求私下提交源码、版本、构建/运行说明、配置/seed、artifact 和 provenance 信息用于复现审查。无法合理复现会影响结果或奖项资格。[Rules §8](https://www.agenthon.net/rules/)

### 待官方确认

- Final 的 CPU、内存、GPU、超时、模型窗口与平台执行安排须看另行发布合同。本文 02 中 Development 的资源不能自动搬到 Final。
- Final 的当前开放状态、descriptor competition ID、实际 private roster、评测版本以及获奖复现容差，需在正式提交前按最新公告核对；本次未登录核实。

| CodaBench 完成后官网未更新 | CodaBench 显示处理状态，agenthon.net 周期同步 validated Development leaderboard；时间不同不自动说明失败 | [官方 FAQ](https://www.agenthon.net/guides/faq/) |

## 8. 数据、行为与许可边界

### 硬性规则

- 私测、隐藏标签、oracle、私有 scoring、canary/audit 材料不得探测、重建、抓取、保留或分享；禁止多账号、串通、利用评分漏洞及 hidden side channels 操纵分数。发现疑似泄漏应停止访问并报告。[Rules §§7、9](https://www.agenthon.net/rules/)、[Licensing §4](https://www.agenthon.net/licensing/)
- 第三方代码、数据、模型的原许可控制其使用与分发；只有 track 允许且有合法权限的资源才可纳入。cutoff 同样约束派生特征、索引、缓存、拟合/微调产物和 synthetic data。T4 更具体的 artifact/training policy 另需遵守。[Licensing §§5–7](https://www.agenthon.net/licensing/)、[固定 T4 ARTIFACT-POLICY](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/docs/ARTIFACT-POLICY.md)、[TRAINING-POLICY](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/docs/TRAINING-POLICY.md)
- 不打包私人数据、凭证、无授权的雇主/客户资料；AI 生成的代码和内容仍由参赛者负责。普通提交不转移所有权，主办方仅取得运行、验证和报道比赛所需的有限授权；普通参赛不要求开源。[Terms §§3–5、7–8](https://www.agenthon.net/terms/)
