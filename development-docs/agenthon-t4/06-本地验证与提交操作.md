## 2. 建立固定版本的本地验证环境

toolkit 与 T4 package 的 `requires-python` 均为 **Python >= 3.13**。这是本地工具要求，不能泛化成自己的 Agent 必须用 Python；参赛程序语言以 CLI、runtime 与依赖兼容为准。

下面是建议目录布局；当前尚未创建 `vendor/` 或 `.venv`，执行时先检查目录是否已有内容，勿覆盖已有工作。

```bash
cd .
mkdir -p vendor
git clone https://github.com/Agenthon-2026/track4-analysis-public.git vendor/track4-analysis-public
git -C vendor/track4-analysis-public checkout 1c744e1d6725340643a533f436517d72b53ca0e1
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install 'qfbench2-common @ git+https://github.com/Agenthon-2026/Agenthon2026-public.git@v2.5.1#subdirectory=common'
```

核对实际加载的 package 与 scorer，不能只看 pip 输出：

```bash
cd ./vendor/track4-analysis-public
python - <<'PY'
import importlib.metadata as md
from qfbench2_track_analysis.scoring import SCORER_VERSION
print('qfbench2-common', md.version('qfbench2-common'))
print('Track 4 scorer', SCORER_VERSION)

```

## 4. 答案验证要覆盖 schema 以外的契约

JSON Schema 会接受一些它无从判断的值，例如不在 task vocabulary 的 label、重复实体、某些 NaN，不能只运行 `jsonschema.validate` 后宣称有效。

推荐用以下示例脚本对每次生成的 answer 做三层检查：schema；可信 task 的 target/roster/numeric 对齐；claim 与 reason advisory rules。把 `unit` 和 `answer_path` 改成相应公开 unit/output 即可。

```bash
python - <<'PY'
import json
from pathlib import Path
from importlib.resources import files
import jsonschema
from qfbench2_track_analysis.alignment import EntityRoster, align_predictions
from baselines.guardrails_example.citation_rail import (
    check_claim_rules, claim_penalty_preview,
    check_submitted_reasons, load_corpus, reasons_judged,
)

unit = Path('units/t4-EXAMPLE-eps-beat')
answer_path = Path('local-runs/minimal/answer.json')
task = json.loads((unit / 'task.json').read_text(encoding='utf-8'))
answer = json.loads(answer_path.read_text(encoding='utf-8'))
schema = json.loads((files('qfbench2_common') / 'schemas/analysis.schema.json').read_text())
jsonschema.Draft202012Validator(schema).validate(answer)
assert answer['task_id'] == task['task_id'], 'task_id mismatch'
align_predictions(
    answer, EntityRoster.from_task(task),
    target_type=task['target']['type'], interval_level=0.90,
)

claim_findings = check_claim_rules(answer, unit)
for finding in claim_findings:
    print('claim', finding.code, finding.entity_id, finding.claim_index, finding.message)
print('deterministic penalty preview', claim_penalty_preview(answer, unit))

corpus = load_corpus(unit / 'corpus')
reason_findings = check_submitted_reasons(answer, corpus, task['cutoff_date'])
for finding in reason_findings:
    print('reason', finding.code, finding.message)
print('reason cap admission preview', reasons_judged(answer, corpus, task['cutoff_date']))

assert not any(f.code == 'unit_refused' for f in claim_findings), 'unit would be refused'
assert not reason_findings, 'reason advisory findings need review'
print('schema and roster/numeric checks passed; review claim findings above')
PY
```

这段脚本故意打印 claim-level false，不把它与整 unit 拒绝混为一谈；工程验收建议要求所有 claim false 清零。`claim_tokens_unchecked` 表示没有 judge tokenizer、400-token cap 未检查，要保留未验证记录；不能当作“已通过全部 claim checks”。reason advisory checker 有 findings 就复查 shape、caps、deny list 与 citation 是否能被 judge 读取。

逐行硬要求包括：`claims` 至少一条；`interval.level = 0.90` 且 `lo <= hi`；classification 有合法 `label`；regression/ranking 有有限 `point_forecast`；所有实体恰好一次；所有 schema 数值有限；可选 `target_type` 与 task 一致；可选 `rank` 全部提供且为 `1..N` 排列。不得漏掉失败行或 NaN 行缩小分母。[schema](https://github.com/Agenthon-2026/Agenthon2026-public/blob/v2.5.1/common/qfbench2_common/schemas/analysis.schema.json)、[alignment](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/alignment.py)、[rails](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/baselines/guardrails_example/citation_rail.py)

## 5. Smoke、NLI 预检和 production 的区别

无模型的 harness 结构 smoke：

```bash
PYTHONPATH="$PWD" qfbench2-smoke \
  units/t4-EXAMPLE-eps-beat local-runs/minimal \
  --track analysis --profile smoke
```

默认 smoke 选择 `build_smoke_verifier`，使用 lexical preview，显式 `rankable=False`。公开 units 无真实 outcome，正常有效答案也会 `score=None`；这不是预测零分或通过正式排名。

完整本地 NLI 预检是可选开发工具，会下载两个模型，需单独评估本地磁盘/算力后执行：

```bash
python -m pip install transformers torch
python faithfulness/judge.py \
  --answer local-runs/minimal/answer.json \
  --unit units/t4-EXAMPLE-eps-beat
```

模型缺失时报告 judge unavailable；`--no-judge` 只能预览确定性规则，不包含 contradiction。下载发生在开发机器，不允许在评测容器运行时下载。不要把本地 NLI 检查器和权重自动放进参赛 Agent 镜像；额外 neural checkpoints 要遵守 artifact policy。

`--profile production` 会选择 `build_verifier`，要求主办方定义的 pinned judge spec/cache 和真实 outcome；所需变量为 `QFBENCH2_T4_JUDGE_SPEC`、`QFBENCH2_T4_MODEL_CACHE`，还核对 revision、tokenizer/cache digests。公开练习包不足以完成 production 排名，不应为了跑通而写假 outcome、关 judge 或修改 gate。本地 `faithfulness/judge.py` 预检也不等于拥有官方完整 production judge artifacts。[smoke runner](https://github.com/Agenthon-2026/Agenthon2026-public/blob/v2.5.1/common/qfbench2_common/smoke.py)、[judge factory](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/qfbench2_track_analysis/judge_factory.py)

## 6. 镜像必须实现的入口和离线 sandbox 检查

正式 verb：

```text
analyze --task /input/task.json --corpus /input/corpus/ --out /output/answer.json
```

镜像接受 `analyze` 作为 image 后的第一个参数：无 ENTRYPOINT 时在 `PATH` 有可执行 analyze；有 ENTRYPOINT 时正确消耗这个 leading positional。必须设置：

```dockerfile
LABEL qfbench2.interface_version="2.0"
```

构建 `linux/amd64`；固定 immutable digest；将依赖和获准 artifact 在 build time 装进 image。构建/推送示例中的 registry/repository/tag 为待选择值，不表示当前已有 registry 或授权发布：

```bash
docker buildx build --platform linux/amd64 \
  -t <registry>/<repository>:<version> --push .
```

Development T4 公开资源为 16 CPU quota、128 GiB memory、每 unit 600 秒；unit card 为执行参数来源。这些不是已承诺 Final 资源。下例模拟 non-root、只读 root、无网络、PIDs、fd、tmp 等约束；`timeout` 是可选本地工具，未安装时用等效 600 秒 supervisor，不能删除超时验收。

```bash
mkdir -p local-runs/container
chmod 777 local-runs/container
timeout 600 docker run --rm \
  --read-only --user 65534:65534 --cap-drop=ALL \
  --security-opt no-new-privileges \
  --tmpfs /tmp:rw,noexec,nosuid,nodev,size=64m \
  --pids-limit 256 \
  --ulimit nofile=1024:1024 --ulimit nproc=256:256 \
  --ulimit fsize=67108864:67108864 \
  --cpus 16 --memory 128g --memory-swap 128g \
  --network=none \
  -v "$PWD/units/t4-EXAMPLE-eps-beat":/input:ro \
  -v "$PWD/local-runs/container":/output \
  -e QFBENCH_SEED=0 -e QFBENCH_NETWORK=none \
  <registry>/<repository>@sha256:<64-hex> \
  analyze --task /input/task.json --corpus /input/corpus/ --out /output/answer.json
```

该测试能暴露 startup、cache path、输出与 fallback 问题，但不能验证 House 可达性、GPU 兼容或官方评分；运行 API-required Agent 需另做获准 House 环境下的检查。正式调用只可使用注入 `$MODEL_ENDPOINT/v1/chat/completions`、`MODEL_NAME`、`MODEL_TOKEN` 与 proxy 环境；不硬编码 endpoint/proxy，不包含个人 API keys。`--network=none` 本地检查需要降级策略，fallback 会牺牲预测效果，必须记录。

镜像大小当前是 **推荐 ≤15 GB，>20 GB may be rejected**，并非已核实自动 enforcement quota。README 说 image-layer limit 是另一项资源，但本次固定公开资料未给出具体层数；“最多20层”尚未确认，不作为硬规则。巨大镜像拉取会消耗 unit wall-clock。[T4 runtime 表](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/README.md#runtime-constraints)、[Development runtime](https://github.com/Agenthon-2026/Agenthon2026-public/blob/v2.5.1/docs/DEVELOPMENT-RUNTIME.md)

## 7. 输出树与镜像可拉取性

仅 `/output/answer.json` 被计分，须 UTF-8 无 BOM JSON，顶层 object。成功退出码为 0；非零退出即便已有输出也会 container_crashed。缺文件为 no_output，不能解析为 malformed_output。

整 `/output` 树还受下列检查：

- 最多 256 files、4,096 files+folders；嵌套深度必须低于 8；不能有 symlink/hardlink/special files。
- 不能有 setuid/setgid/sticky 权限、超过已占磁盘空间 64 倍的 sparse file。
- 名称须合法 UTF-8/NFC；不能有仅大小写/Unicode 形式不同的冲突、反斜杠、control chars、Windows 风格顶层 `C:`。
- 总树和单文件均最多 64 MiB；无 files 或树不合规也会 no_output。Final 适用同样总输出 cap。

Root read-only，`/tmp` 只有 64 MiB 且 noexec，不能假定可写 home、下载包、JIT 到任意路径。建议仅保留 answer 和必要的小日志，避免输出整个检索 cache。没有真实执行之前，不能声称通过这些限制。[输出与失败约定](https://github.com/Agenthon-2026/track4-analysis-public/blob/1c744e1d6725340643a533f436517d72b53ca0e1/README.md)

`image_access: public` 要求匿名按 digest 拉取。工作站登录状态下 docker pull 成功不能证明匿名可用；应在无 registry credentials 的环境测试 exact manifest 与 layers。GitHub repository public 不等于 GHCR package public。若必须私有，先获得主办方对 private handoff 和具体 reference 的确认；`organizer_mirror` 字段不会配置权限，也不意味着已可提交。[镜像提交说明](https://github.com/Agenthon-2026/Agenthon2026-public/blob/v2.5.1/docs/IMAGE-SUBMISSIONS.md)

## 8. `submission.json` 及两种 digest

直接从官方 fixture `contracts/fixtures/c5/analysis_dev.json` 起步，修改真实字段并重封。不使用网站旧示例中的 `byo-large` / `byo-small`；v2.5.1 parser/schema 只允许 `api` / `simulator`，T4 为 **api**，不使用模型的 deterministic T4 也为 api 且 `models: []`。

十二个 required keys：

```text
schema_version interface_version competition_id team_id track phase category
image image_access models license descriptor_digest
```

其中：

- `interface_version: "2.0"`，与 label 一致。
- Development：`competition_id: "agenthon2026-analysis-dev"`、`track: "analysis"`、`phase: "dev"`、`category: "api"`。parser 不会帮忙验证 competition_id 的具体 track/phase 拼接或 category-track 组合，需人工复核。
- `image` 是 registry/repository/digest **对象**，不是 image 字符串；digest 为 `sha256:<64 lowercase hex>`，不用 floating tag。
- `models` 必須存在；House 使用时声明真实 five-field metadata；model-free 是空数组，不发明模型行。
- `license` 是自己提交代码的合适 SPDX/OSI-approved license，不是给官方 corpus 重授权。
- `descriptor_digest` 是去掉该字段后，对 descriptor 的 RFC 8785/JCS canonical bytes 计算的 SHA256，与 image.digest 是不同对象；用 toolkit，不手算 `json.dumps(sort_keys=True)`。
- descriptor 不接受 unknown keys；不要添加 `house_endpoint_only`、`open_weights`、`api_domains`、`image_digest`、`model_disclosure` 或 credentials。

House disclosure（实际用了才放进 models）：

```json
{
  "name": "nvidia/nemotron-3-super-120b-a12b",
  "version": "rl-030326-fp8",
  "revision": "rl-030326-fp8",
  "training_cutoff": "unpublished",
  "access": "api"
}
```

`unpublished` 是官方未公开训练 cutoff，不能替换成猜测日期或 release date。调用时用注入 `MODEL_NAME`，route alias 与 disclosure identity 不同。[descriptor guide](https://github.com/Agenthon-2026/Agenthon2026-public/blob/v2.5.1/starter-packs/track4/SUBMISSION-DESCRIPTOR.md)、[当前 parser](https://github.com/Agenthon-2026/Agenthon2026-public/blob/v2.5.1/common/qfbench2_common/contracts/descriptor.py)、[House identity](https://github.com/Agenthon-2026/Agenthon2026-public/blob/v2.5.1/docs/HOUSE-MODEL.md)

先获取 team alias，Team Key 仅在 hidden prompt 输入：

```bash
qfbench2 submission alias --team-number <团队数字编号>
```

然后将输出的 alias 写入 descriptor `team_id`，不要保留 fixture 中的 `team-example-0001`。Website Team Number 与 derived team_id 不同；`pack` 会拒绝与实际 alias 不符的 team_id。

从 installed toolkit 复制 fixture、替换真实数据并 reseal 的示例。先将以下内容保存为开发工作目录的 `prepare_submission.py`，再在可交互终端运行 `python prepare_submission.py`：

```python
import json
from pathlib import Path
from importlib.resources import files
from qfbench2_common.contracts.descriptor import seal_descriptor_digest, SubmissionDescriptor

descriptor = json.loads((files('qfbench2_common') / 'contracts/fixtures/c5/analysis_dev.json').read_text())
descriptor['team_id'] = input('Derived team_id（非 Team Key）: ').strip()
descriptor['image'] = {
    'registry': input('Image registry: ').strip(),
    'repository': input('Image repository: ').strip(),
    'digest': input('Image digest（sha256:...）: ').strip(),
}
descriptor['image_access'] = 'public'  # 私有镜像仅在主办方确认后改 organizer_mirror
descriptor['license'] = input('Submission SPDX license: ').strip()
uses_house = input('实际使用 House model？输入 yes 或 no: ').strip().lower()
assert uses_house in {'yes', 'no'}
descriptor['models'] = [] if uses_house == 'no' else [{
    'name': 'nvidia/nemotron-3-super-120b-a12b',
    'version': 'rl-030326-fp8', 'revision': 'rl-030326-fp8',
    'training_cutoff': 'unpublished', 'access': 'api',
}]
descriptor = seal_descriptor_digest(descriptor)
SubmissionDescriptor.from_mapping(descriptor)
Path('submission.json').write_text(json.dumps(descriptor, indent=2) + '\n', encoding='utf-8')
print('sealed submission.json; still verify anonymous image access and track/phase manually')
```

Team Key 始终不进入该脚本。`input()` 仅询问 image 与提交身份等非敏感 descriptor 字段；team-claim 的 key 输入留给 toolkit hidden prompt。

除了 JSON Schema，还必须调用 `SubmissionDescriptor.from_mapping` 校验 canonical digest；错误 descriptor_digest 可以通过 JSON Schema 却被 parser 拒绝。字段或 image 重建后务必 reseal/repack。

## 9. ZIP、团队证明与上传

```bash
qfbench2 submission pack \
  --descriptor submission.json \
  --team-number <团队数字编号> \
  --out submission.zip
```

该命令本地执行，不会上传或消耗次数；已有 zip 时需显式 `--force` 替换。终端不能隐藏输入时被拒绝，可用 `--team-key-file <本地私密文件>`，文件为自己所有、mode 600、regular file、只含 key。不要把 Team Key 作为命令行参数或写入文档、日志、模型 prompt、镜像、仓库。

ZIP 根目录只能有：

| 文件 | 内容 |
|---|---|
| `submission.json` | sealed descriptor |
| `team-claim.json` | `schema_version: "2.0"`、website 数字 `site_team_id`、同 ZIP descriptor 精确字节的 SHA256、HMAC proof |

Team Key 不进 ZIP，`team-claim` 不是 registry credential。不要打印 proof、把 ZIP 发到公开 issue 或记录私密包内容。一个团队所有赛道使用同一指定 CodaBench account；第一次有效 claim 绑定团队，之后每个 ZIP 继续附 claim。[team claim guide](https://github.com/Agenthon-2026/Agenthon2026-public/blob/v2.5.1/starter-packs/track4/TEAM-CLAIM.md)、[打包实现](https://github.com/Agenthon-2026/Agenthon2026-public/blob/v2.5.1/common/qfbench2_common/team_claim.py)

不泄露 claim 内容的本地包检查：

```bash
python - <<'PY'
import hashlib, json, zipfile
from qfbench2_common.contracts.descriptor import SubmissionDescriptor
with zipfile.ZipFile('submission.zip') as archive:
    assert sorted(archive.namelist()) == ['submission.json', 'team-claim.json']
    raw = archive.read('submission.json')
    desc = json.loads(raw)
    SubmissionDescriptor.from_mapping(desc)
    claim = json.loads(archive.read('team-claim.json'))
    assert claim['schema_version'] == '2.0'
    assert claim['descriptor_sha256'] == hashlib.sha256(raw).hexdigest()
    assert desc['track'] == 'analysis' and desc['category'] == 'api'
    assert desc['phase'] == 'dev' and desc['competition_id'] == 'agenthon2026-analysis-dev'
print('ZIP members, descriptor and byte binding checked; proof verification remains organizer-side')
PY
```

首上传无 claim/unreadable claim、wrong proof、unknown team number、账户/团队冲突等通常 held；已绑定 account 的 descriptor team_id 不符会 cancelled (`descriptor_team_mismatch`)。网站不可达 linking 也可能 held，不能把全部 held 当 Agent 运行失败。重新上传消耗新次数；状态不清先用 submission id/可见状态联系支持，不发送 key、proof 或 credential。

在已登录 agenthon.net account 找本赛道 competition link，指定账户申请 CodaBench entry、按页面审批/terms 步骤，然后 My Submissions → Development 上传 `submission.zip`。页面可用性以登录公告为准，本手册不宣布服务已开放。[官网提交步骤](https://www.agenthon.net/guides/submission-format/)
