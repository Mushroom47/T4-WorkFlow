# 二次开发工作流与 Linear 同步

本项目按用户指定的 `local-docs-index`、`development-docs-linear-sync`、`linear-phase-workflow` 初始化。此工作流由明确任务触发，不后台监听代码或自动更新比赛规则。

## 开发前

1. 用 `find` 或 `ls -la` 确认本地文档目录，包含 Git 忽略的资料。
2. 读取任务入口、当前规则/来源、模块与 Phase、进度、问题与决策及 Linear 映射。
3. 获取当前 Phase issue，核对目标与验收标准；只在实际开始该阶段时转为进行中。
4. 官方规则和发布说明具有时效性；构建候选、模型选择或比赛提交前重新核对。

## 记录与证据

规则类型使用“硬性要求”“Development 条件”“评分规则”“建议”“待确认”。状态使用“未开始”“方案设计中”“开发中”“已完成”“暂缓”。“规则已核对”不代表“实现已满足”。

验证记录至少包含日期、版本/输入、精确命令、退出码/结果、变更文件、限制与后续事项。文件检查、组件测试、实际容器、真实 House 调用和官方平台结果分别记录；不能用 smoke 或 mock 代替预测质量。

## Linear 职责

- 层级：Initiative → Project → Phase issue；本地保存详细材料，Linear 保存共享规则摘要、验收、依赖和状态。
- 写入前确认 Workspace 和 Team；有多个连接器时逐个只读核实。目标不匹配时禁止写入。
- 每次创建/更新 issue、文档、项目后，用同一连接器回读身份、归属、状态和内容。列表/search 的归档信息可能不完整，必要时用详情与实际返回警告核对。
- 优先复用有效对象；不恢复归档对象来绕过归属问题。本轮旧 I-13 关联被拒绝，已建立 I-14，记录见 [Linear 映射](agenthon-t4/11-Linear映射.md)。
- 不超过 5 个 Phase 直接建立卡片；超过 5 个先讨论粒度。Done 只表示当前 Phase 验收满足；项目仍有后续阶段时保持进行中。
- Linear 不可用时保存手动更新包，继续独立本地工作，并报告同步未执行。

## 完成后

更新 Phase 与模块状态，追加进度，记录重要决策；运行适合本次改动的验证并同步 Linear。评论包括更新摘要、变更文件、调试记录、验证结果、结果、剩余风险/后续事项。

凭据只记录变量名、路径与占位符；不写真实 Team Key、`MODEL_TOKEN`、API key、密码、私钥、登录状态或完整敏感连接串。
